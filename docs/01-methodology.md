# 01 · 方法论沉淀说明

> 本文档解释 ai-pm-hub 的方法论是怎么从「方法论学习的素材」沉淀成「跨领域通用框架」的。
> 理解这个过程，你就能判断本仓库的内容可不可信、能不能用。

> **重要前提**：本仓库的样例来源于第三方培训/学习材料，已做去行业化处理。**沉淀的是方法论骨架，不是任何特定项目或培训内容的复制**。详细权利划分见 [NOTICE](../NOTICE)。

## 核心思想

**学的是「方法论骨架」，不是「行业知识」**。

| 学到 | 没学 |
|------|------|
| 怎么把信息架构画成「端 × 层」矩阵 | 具体某产品的页面树长什么样 |
| 状态机必须给状态枚举、转移条件、超时与失败态 | 某行业系统的具体 5 个失败态 |
| 多引擎降级要按精度切 | 某个 OCR 引擎的具体配置 |
| 假设的置信度要 4 级量表 | 某个项目面临的 12 个具体假设 |
| 评测体系分层 L0–L6 | 某个 LLM 在某类题上的具体通过率 |

每一份 `references/*.md` 文件，**都是从「方法论应该长什么样」的角度抽象出来的骨架**——具体行业的功能模块名、数据格式、API 细节都不出现。

## 沉淀的 4 步流程

### 1. 金标准对齐

从已有沉淀好的方法论技能（如 `market-insight-writer`、`prd-style-learner`）作为「金标准」：
- SKILL.md 的章节编排（核心理念 / 一句话定位表 / 输入链 / 通用工作流 / 如何按需加载框架 / 跨领域适配规则 / 输出约定 / 注意事项）
- reference 文件的五段式结构（`## 回答什么问题` / `## 怎么分析` / `## 怎么写` / `## 及格线` / `## 最易挂的坑`）

> 新加的 reference 必须符合这个结构。

### 2. 抽样摸骨架

**素材是「方法论应该长什么样」的参考，不是「事实陈述」**。先用「只读抽样」摸清每份素材的章节结构：

```bash
# 提取所有标题骨架（python + regex）
python3 -c "
import re
for f in glob('docs/*.md'):
    s = open(f).read()
    print(f, '—', len(re.findall(r'^## ', s, re.M)), '节')
"
```

判断哪些章节是「跨领域通用的方法论骨架」，哪些是「仅适用特定场景的描述」。

### 3. 并行拆解 + 去行业化

**并行**：把多份素材拆给 3–5 个子代理同时提炼，每个子代理读自己的素材 + 对齐金标准 + 写 reference。

**去行业化**：在写 reference 时严格遵守两条规则：
- ✅ 框架层用通用表述（「核心用户角色」「该领域的滩头区域」）
- ❌ 禁止把行业专属素材（具体产品名、具体技术栈、具体地域）当作方法论写进框架

质量检查：
```bash
# 反向检查：reference 文件中不应出现具体行业专属词
grep -E "具体产品名|具体地域|具体厂商" skills/*/references/*.md
# （命中应为 0；命中要么删、要么用通用表述替换）
```

> macOS 的 BSD `grep` 对中文 `|` 交替会静默漏检，**必须用 `grep -E`**。

### 4. 质检验收

对每个 reference 检查：
- [ ] 行业专属词命中数 = 0
- [ ] 五段式结构完整（5 个 `##` 标题按顺序）
- [ ] 每段都有「方法论要点」+「可执行细节」（如状态机要给状态枚举、矩阵要给行列定义、算法要给可复现步骤）
- [ ] 开头有 `> 源文档：XX-XXX.md`（可回溯到源材料，但不暴露源材料具体内容）
- [ ] 不少于 70 行（过短说明方法论没写透）

## 沉淀过程的「红线」

沉淀时如果出现这些信号，停下来检查：

1. **出现「待补充 / TODO / XXX 待定」**——说明方法论还没想透，先回去想
2. **「跟 ChatGPT 一样的话」**——说明写的是常识而非方法论，需要更深一层
3. **每节都超长且没表格**——说明内容在堆砌，方法论应该结构化
4. **离开源材料就讲不清楚**——说明依赖了具体内容，没去方法论化
5. **读者换场景后完全不能用**——说明方法论没脱耦，需要抽象

## 沉淀过程的「绿灯」

这些信号说明沉淀做得好：

- ✅ 把行业专属词替换成通用词后，行文不出现奇怪的空白或跳脱
- ✅ 换 3 个完全不同的领域（如教育→金融→医疗），reference 都能直接套用
- ✅ 及格线 4–6 条能逐条 ✓ 验证而非泛泛而谈
- ✅ 最易挂的坑 2–4 条都是「经典错误」而非「细节挑刺」
- ✅ 状态机、矩阵、降级链都有可执行的细节（状态枚举、列定义、降级顺序）

## 与「传统文档模板」的区别

| 传统文档模板 | ai-pm-hub reference |
|-------------|---------------------|
| 给「模板」让用户填空 | 给「方法论」让用户判断 |
| 通用但浅（任何场景都适用、任何场景都无指导性） | 跨领域但深（能跨领域、能给具体决策标准） |
| 只有结构没有「及格线」 | 五段式最后两段是「及格线 ☑ 清单」+「最易挂的坑」 |
| 一份文档回答「长什么样」 | 一份文档回答「怎么写、写到哪算够」 |

## 沉淀来源的合规性

本仓库的**方法论框架**为作者原创沉淀。**样例（`_example-*.md`）** 是基于第三方培训/学习材料中方法论应用方式的**重构**——只保留方法论骨架，不复制任何原始素材的实质性内容。读者应：

- 视样例为「方法论的呈现示例」，不是事实陈述
- 不应将样例中的占位符替换为真实产品名后当作事实证据
- 详细权利划分与免责条款见 [NOTICE](../NOTICE)

> 反抄袭与去行业化的具体做法，详见 [docs/02-anti-plagiarism.md](02-anti-plagiarism.md)。
