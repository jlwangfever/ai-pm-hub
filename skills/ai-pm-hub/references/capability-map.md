> 这是 AI 产品经理方法论的**能力清单**，也是本 skill 未来扩充的**唯一主表**。
> 能力编号 = 流程段位（第 1-7 段），一套编号，不搞两套。新增能力：在这里加一行；SKILL.md 的能力地图表、路由规则、编排链路同步更新。

## 八段流程（能力之间的编排）

```
1 市场洞察 → 2 用户与价值定义 → 3 验证与商业模式 → 4 产品设计 → 5 PRD → 6 DESIGN.md → 7 原型设计 → 8 UI 实现
```

各段内部顺序与源文档编号：

| 段 | 能力 | 段内顺序 | 源文档编号 |
|----|------|---------|-----------|
| 1 | 市场洞察 | PESTLE → 市场规模 → SWOT ⇄ 竞品 → 产品愿景 | 01–05 |
| 2 | 用户与价值定义 | 用户画像 → 价值主张 → ICP → 定位 → 滩头 | 06–10 |
| 3 | 验证与商业模式 | 验证线 假设 → 机会树 → Pre-Mortem；商业线 精益画布 → 北极星 → GTM → 功能优先级；干系人贯穿 | 11–18 |
| 4 | 产品设计 | 八层递进：信息架构 → 流程与权限 → 业务系统 → Agent → 数据与分析 → 支撑系统 → 技术基础 → 前端整合 | 19–40、42 |
| 5 | PRD | 先 learn（风格档案）→ 再 write（按风格写） | 独立 PRD 文档 |
| 6 | DESIGN.md | 提取设计参数 → 抽象组件模式 → 翻译约束规则 → 整体约束与缺口表 | 衍生自 35 + 38（43 号框架） |
| 7 | 原型设计 | 七维度方案 → Review 三关 → 原型生成 → 需求标注追溯码 → 原型说明文档 | 41、44 |
| 8 | UI 实现 | 问框架 → 选组件库 → 对组件名 → 写代码 → 要迭代 | 45 |

> 源文档编号指这套方法论最初被提炼时的原始素材（一个真实项目的 01–42 号成品文档）；技能里只保留抽象后的框架与示范样例，行业素材不入库。

**段间承接（文档不孤立，下一段以上一段为依据）**：完整承接表见 `SKILL.md` 跨能力编排一节。第 7 段的输入 = 第 4 段设计文档（长什么样）+ 第 5 段 PRD（验收什么）；第 6 段的输入 = 35 设计系统 + 38 前端规格；第 8 段的输入 = 43 DESIGN.md（视觉约束）+ 第 7 段原型（交互与状态基准）。

## 每个能力的标准信息（扩充时按此模板补全）

新能力纳入前，确认以下四项都已明确：

1. **能力名**：一句话能说清（如「市场洞察」「用户与价值定义」）。
2. **做什么**：覆盖哪些子文档 / 子环节，一句话描述。
3. **触发词**：用户会怎么自然地说出这个需求（≥3 个）。
4. **产出物**：最终交付什么（Markdown / 表格 / 档案 / Word / HTML…）。

如果四项填不满，说明该能力还没想清楚，暂缓纳入（先进下方备忘区）。

## 当前未覆盖但可能扩充的方向（备忘）

- **竞品深挖**：单竞品深度拆解（横向对比已在 1 段 04 与 3 段 17 中）
- **立项与商业计划**：立项书、BP、融资叙事（GTM 已在 3 段 17 覆盖）
- **增长与留存实验**：增长模型、留存曲线、实验设计与统计显著性（当前只有功能优先级排序）
- **数据与埋点方案**：把指标体系落成埋点表与数据字典（当前有北极星指标，但没有埋点规范）
- **硬件 / 供应链类设计**：BOM、结构评审、工业设计（当前产品设计偏软件）

> 这些只是备忘，不构成承诺；纳入前仍须走「扩充指南」四步，纳入时按流程段位接在第 7 段之后或插入对应段位并全线重排编号。
