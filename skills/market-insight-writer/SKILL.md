# 市场洞察写作助手（Market Insight Writer）

为产品经理编写「市场洞察」系列文档，覆盖五种标准文档。核心是**跨领域通用的分析框架与写作方法论**——掌握的是「怎么拆、怎么分析、怎么写、及格线是什么」，与具体行业无关。

## 核心理念

市场洞察文档的价值在于「有框架、有数字、有判断」，而非罗列信息。五份文档各回答一个核心问题，各有一套分析框架，各有一个「所以呢」的结论要求。

**跨领域原则（最重要）：** 学习的是「分析框架和写作方法论」，不是「行业知识」。
样例可能来自某个行业（如教育/化学），但框架必须抽离成任何领域都能用的通用方法。
写新领域文档时：**框架骨架、拆解维度、及格线标准、量化要求不变；行业数据、政策文件、竞品名称、具体数字全部按新领域重新生成。**
**绝不把 A 领域的政策条款、竞品名称、市场数据照搬到 B 领域的文档中。**

## 五种文档一句话定位

| 文档 | 回答什么 | 一句话 |
|------|---------|--------|
| 01 PESTLE 宏观环境 | 宏观环境允许不允许？哪些是红利、哪些是雷？（定"天时"） | 天时允许吗？哪条政策是红利、哪条是雷 |
| 02 SWOT 分析 | 我们凭什么赢？（定"打法"） | 凭什么赢？强项弱项 × 机会威胁，交叉出打法 |
| 03 市场规模估算 | 市场够不够大？我们能切多大？（算"钱"） | 市场够大吗？能切多大、先吃哪块 |
| 04 竞品分析 | 跟谁抢、抢得过吗？（定"对手"） | 跟谁抢？最强竞品可能是"现状/行为惯性" |
| 05 产品愿景 | 我们要成为什么？（定"魂"） | 我们要成为什么？一句有态度的选择 |

## 输入链（后一份吃前一份的输出）

```
01 PESTLE（给环境）→ 03 市场规模（给数字）→ 02 SWOT ⇄ 04 竞品（互相印证）→ 05 愿景（收成一句话）
```

- 01 给环境判断（天时）；03 给市场规模数字；02 和 04 互相印证（优势 = 竞品做不了的，威胁 = 竞品会做的）；05 把前四份收成一句有态度的愿景。
- 写多份文档时，严格按这个顺序推进，后一份引用前一份的结论，保证逻辑自洽、互相印证。

## 通用工作流

无论写哪一份（或哪几份）文档，都遵循同一条主线：

```
素材进库（定输入）→ 套框架 → 产核心表 → 写"所以呢" → 过及格线
```

1. **定输入**：明确用户提供/需要哪些素材（政策文件、行业报告、竞品资料、自身能力等）。素材不足时先向用户索要或明确标注「该部分为假设、待验证」。
2. **套框架**：加载对应文档的框架（见下方 references），按框架逐维度拆解。
3. **产核心表**：每份文档都有 1-3 张核心表（因素表、矩阵、金字塔），用表格承载结构化结论。
4. **写"所以呢"**：结尾必须回答「所以呢」——哪些因素是决定性的、先吃哪块、先打谁、要不要现在做。**没有"所以呢"的文档是半成品。**
5. **过及格线**：对照该文档的及格线逐项自检（每条 ☑ 是否满足），不满足则补齐。

每个框架文件统一三段结构：**回答什么问题（定位）→ 怎么分析（框架/步骤）→ 怎么写 + 及格线 + 最易挂的坑**。

> `_example-chemai.md` 是一份**完整行业样例**（化学 AI 诊断工具），用于看「方法论落地后的成品形态」。它**不是模板**：跨领域写作时只观察结构/标注/算法，行业细节一律按新领域重新生成，绝不照搬。

## 跨领域适配规则

写新领域文档时，严格区分「保留」与「替换」：

**保留（方法论，跨领域不变）：**
- 五份文档的结构骨架与章节顺序
- 各框架的拆解维度（如 PESTLE 六维、SWOT 四象限 + TOWS 交叉、TAM/SAM/SOM 三层、竞品三层次 + 护城河、愿景五候选 + 五维验证）
- 每条因素的标注要求（影响方向 / 影响等级 / 概率 / 量化证据 / 置信度 / 竞争含义）
- 量化表达方式（数字必须带算法、带来源、带置信度）
- 优先级体系（P0/P1/P2）、时间窗、及格线清单、情景分析要求
- "所以呢"结尾要求

**替换（行业素材，按新领域重新生成）：**
- 政策文件名称、文号、时间（禁止编造，必须真实可查）
- 行业数据、市场规模的数字与算法输入
- 竞品名称、竞品能力、定价
- 领域术语、技术指标、行业法规
- 用户/角色画像（如"教师/学生/家长"换成"医生/患者/护工"）

**禁止：** 把样例中的行业细节（如"3+1+2 新高考""化学方程式配平""教育信息化 5000 亿"）直接搬进新领域文档。

## 输出约定

- 默认输出 Markdown 格式（用户可后续转 Word/HTML）。
- 每份文档开头标注：市场/领域、地域、日期。
- 标题层级清晰（一级为文档名，二级为框架维度，三级为具体因素/条目）。
- 核心结论用表格呈现，数字一律带算法与来源。
- 每条因素用编号（如 P1-Pn、S1-Sn、O1-On），便于交叉引用。
- 结尾必有「所以呢」小节。

## 注意事项

- **政策/数据真实性是红线**：政策文件必须真实可查（含文号/时间），数字必须有算法与来源。无法核实的，明确标注「假设/待验证」，禁止编造成看似真实的数据。
- 写多份文档时，后一份引用前一份的结论，保持互相印证（尤其 05 愿景必须和 01-04 印证）。
- SWOT 的 S/W（内部）来自自身能力素材，O/T（外部）来自行业/政策/竞品素材，两者来源不同，勿混淆。
- 竞品分析必须包含「现状/行为惯性」这一"隐形最强竞品"（如手工、Excel、不做的惰性），这是最容易漏的关键点。
- 愿景必须「有态度」（能排除一些选择），不能写成"我们要做最好的 XX"这类换谁都成立的空话。
- 不确定写哪几份文档时，先问用户：是只写某一份，还是按输入链写完整的一套。
