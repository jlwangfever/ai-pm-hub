# 01 PESTLE 宏观环境分析框架

## 回答什么问题

宏观环境允许不允许？哪些是红利、哪些是雷？（为整个项目定「天时」）

核心产出：判断「要不要现在入场」「哪些外部因素是决定性的」。

## 怎么分析

### 1. PESTLE 六维拆解

六个维度各拆出带编号的因素：

- **P（Political 政治）**：政策导向、产业扶持/监管、政府考核指标、改革方向
- **E（Economic 经济）**：宏观景气、成本结构（原材料/API/人力）、付费能力、投融资环境
- **S（Social 社会）**：社会认知、人群结构、观念变迁、焦虑/刚需心理、代际差异
- **T（Technological 技术）**：关键技术成熟度、成本下降曲线、基础设施、数据积累
- **L（Legal 法律）**：隐私/数据法规、行业准入/备案、知识产权、安全法规
- **En（Environmental 环境）**：环保/ESG、可持续性（通常影响较低，可精简）

每个维度产出带编号的因素（P1-Pn、E1-En、S1-Sn、T1-Tn、L1-Ln、En1-Enn）。

### 2. 每个因素标注三个属性

- **影响方向**：机会 / 威胁 / 中性（偏机会/偏威胁）
- **影响等级**：低 / 中 / 中高 / 高 / 极高
- **概率**：确定 / 高 / 中 / 低

格式示例：`P1：xxx 政策（机会 -- 影响等级：极高，概率：确定）`

### 3. 政策因素真实性红线

- 政策因素一律以真实政策文件为准（含文号/发布时间），禁止编造。
- 每条政策写清：文件名称 + 发布时间 + 关键条款 + 对项目的具体影响。

### 4. 补充分析（提升深度，非必选但建议）

- **政策时间线**：关键里程碑 + 转折点（哪些事件改变了行业走向）
- **风险热力图**：按地域/维度标风险等级（高/中/低）
- **What-If 情景分析**：至少 1 个「最坏合理情况」（如政策收紧、技术停滞、大平台入场、供应链断裂）；最好加 1 个「最好情况」
- **总结矩阵**：把六维收进一个矩阵标优先级 + 综合评分

## 怎么写（结构）

1. **摘要**：核心结论 + 最大战略风险
2. **六维因素表**：每维 3-8 条，每条带编号 + 方向 + 等级 + 概率 + 影响分析
3. **政策时间线**（如适用）
4. **情景分析**（What-If，含最坏合理情况）
5. **总结矩阵**：四象限决策矩阵（影响程度 × 发生概率），标出战略重点
6. **「所以呢」**：哪 2-3 个因素是决定性的、要不要现在入场

## 及格线

- ☑ 六维都有因素
- ☑ 政策真实可查（文号/时间）
- ☑ 每条标影响方向
- ☑ 有情景分析（至少 1 个「最坏合理情况」）
- ☑ 有「所以呢」（哪些因素决定做不做）

## 最易挂的坑

- **政策是编的**：必须用真实政策文件，不能凭印象写政策名。
- **只罗列不收敛**：列了一堆因素，却没回答「哪些因素决定行动」。
