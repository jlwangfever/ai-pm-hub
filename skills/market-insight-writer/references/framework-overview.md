# 市场洞察分析框架总览

> 为五份市场洞察文档补齐「数据从哪来 → 怎么分析 → 怎么写 + 及格线」。
> 本文件是总览，每份文档的详细框架见同目录下 01-05 各文件。

## 一、素材 → 文档对应（写哪份，喂哪类素材）

| 素材类型 | 喂给哪份文档 |
|---------|------------|
| 政策文件 / 法规摘录 | 01-PESTLE（P/L 维）、05-愿景（政策对齐） |
| 行业公开报告片段 / 新闻与政策剪报 / 行业数据 | 01-PESTLE（E/S/T 维）、03-市场规模 |
| 竞品官网与价格页摘录 / 竞品调研记录 | 04-竞品、02-SWOT（O/T）、05-愿景（竞品论证） |
| 自身能力 / 成本 / 团队 / 数据资产 | 02-SWOT（S/W） |

> **注意（02-SWOT 跨库）**：02-SWOT 的 S/W（内部优劣势）输入来自**自身能力素材**（功能、成本、团队、数据），不是外部洞察素材。O/T（外部机会威胁）来自行业/政策/竞品素材。跑 02-SWOT 需同时具备内部与外部两类素材。

## 二、一句话话术（五份文档 3 秒定位）

| 文档 | 一句话 |
|------|--------|
| 01 PESTLE | 天时允许吗？哪条政策是红利、哪条是雷 |
| 02 SWOT | 凭什么赢？强项弱项 × 机会威胁，交叉出打法 |
| 03 市场规模 | 市场够大吗？能切多大、先吃哪块 |
| 04 竞品 | 跟谁抢？最强竞品可能是「现状/行为惯性」 |
| 05 愿景 | 我们要成为什么？一句有态度的选择 |

## 三、输入链（01 → 03 → 02 ⇄ 04 → 05）

- 01 PESTLE 给环境（天时），03 市场规模给数字，02 和 04 互相印证（优势 = 竞品做不了的，威胁 = 竞品会做的），05 把前四份收成一句有态度的愿景。
- 后一份吃前一份的输出——这是多份文档能快速、自洽产出的真正原因。
- 写全套时严格按此顺序；写单份时也要清楚它在这条链上的位置，引用上下游结论。

## 四、统一写作主线

```
素材进库（定输入）→ 套框架 → 产核心表 → 写"所以呢" → 过及格线
```

每份文档都必须：有结构化框架 → 有 1-3 张核心表 → 有「所以呢」结论 → 过及格线自检。

## 五、及格线总表

| 文档 | 及格线（每项都须满足） |
|------|---------------------|
| 01 PESTLE | 六维都有因素；政策真实可查（文号/时间）；每条标影响方向；有情景分析（≥1 个最坏合理情况）；有「所以呢」 |
| 02 SWOT | S/W/O/T 四象限都有编号+量化证据；有 TOWS 交叉策略（非只罗列四象限）；有反直觉洞察；结论是「所以呢」；每个因素标竞争含义 |
| 03 市场规模 | 每个数字有算法（非拍脑袋）；有敏感性分析；TAM/SAM/SOM 三层边界清楚；数据来源可查（标置信度）；有「所以呢」 |
| 04 竞品 | 竞品分三层次；有对比表（能力/价格/弱点）；含「现状/行为惯性」竞品；有赢/输场景；有护城河分析；结论指导「先打谁」 |
| 05 愿景 | 愿景是有态度的表达（能排除选择）；有决策链（愿景→哪些决策）；和 01-04 互相印证；有验证框架（能被打分/被证伪） |

## 六、统一红线（所有文档通用）

1. **政策/数据真实性**：政策文件必须真实可查（文号/时间），数字必须带算法与来源。无法核实的标注「假设/待验证」，禁止编造。
2. **每条因素带量化与标注**：因素不能只给形容词，要带影响方向、等级、概率或量化证据、置信度。
3. **结尾必有「所以呢」**：没有决策含义的文档是半成品。
