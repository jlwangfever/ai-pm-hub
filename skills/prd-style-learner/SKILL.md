# PRD 风格学习与写作助手

学习你已有 PRD 的写作风格，以后按你的风格辅助生成新 PRD。

## 核心理念

每个人的 PRD 风格不同——结构编排、章节命名、颗粒度粗细、用词习惯、表格 vs 列表的偏好都不一样。
这个 skill 不套用通用模板，而是从你自己的 PRD 中提取风格特征，形成「风格档案」，以后写作时套用。

**跨领域原则（重要）：** 学习的是「写作方法论和风格 DNA」，不是「行业知识」。
用户的 PRD 可能来自不同行业（CV/NLP/金融/车载…），风格档案必须提取跨领域通用模式，
并明确区分「保留不变的方法论」与「按新领域替换的素材」（见档案第五节「跨领域适配规则」）。
写新领域 PRD 时：骨架、量化方式、优先级体系、数据链条方法论不变；行业数据、技术指标、法规内容按新领域替换。
**绝不把 A 领域的技术细节（如 FID 指标、DCF 模型）照搬到 B 领域的 PRD 中。**

## 三种模式

### 模式一：learn — 学习已有 PRD

触发词：「学习我的PRD」「分析我的PRD风格」

**流程：**

1. 用户提供一个或多个 PRD 文件路径（支持 .docx / .pdf / .md 三种格式）
2. 根据格式选择解析方式，提取结构化文本：

   **Word（.docx）**：
   ```bash
   /Users/jlwang/.workbuddy/binaries/python/envs/default/bin/python \
     ~/.workbuddy/skills/prd-style-learner/scripts/parse_docx.py \
     "<PRD文件路径>"
   ```

   **PDF（.pdf）**：
   ```bash
   /Users/jlwang/.workbuddy/binaries/python/envs/default/bin/python \
     ~/.workbuddy/skills/prd-style-learner/scripts/parse_pdf.py \
     "<PRD文件路径>"
   ```

   **Markdown（.md）**：跳过脚本，直接用 Read 工具读取全文即可。

3. 阅读解析输出，分析以下维度并形成风格档案（多份样本时重点提取**跨样本共性**）：

   **结构维度（跨领域通用骨架）：**
   - 章节顺序与命名（如：背景 → 目标 → 范围 → 功能详述 → 非功能性需求 → 里程碑）
   - 层级深度（通常到几级标题）
   - 每个章节的典型内容模式和篇幅

   **风格维度（写作 DNA）：**
   - 语气与正式程度（正式 / 半正式 / 口语化）
   - 句式偏好（短句为主 / 长句为主 / 混合）
   - 是否定量描述（用数字、百分比、具体指标）
   - 人称使用（第一人称 / 第三人称 / 无主语祈使句）
   - 标志性表达习惯（如星级标记⭐️、版本演进叙事、通俗比喻、Callout 框等）

   **格式维度：**
   - 表格使用频率和典型列结构
   - 列表 / 子弹点的使用模式
   - 是否包含流程图描述、状态机、时序图等
   - 是否包含验收标准（AC）、优先级标记（P0/P1/P2）

   **术语维度（区分「通用方法论术语」与「领域专属术语」）：**
   - 通用方法论术语（跨领域保留）：如 MECE、P0/P1/P2、用户旅程、MVP、数据标注质控流程
   - 领域专属术语（不跨领域照搬）：仅记录用于理解，写新领域 PRD 时不外推
   - 角色名称（如「需求方」「开发负责人」「QA」）
   - 状态值枚举（如需求状态：待评审 / 开发中 / 已上线）

4. 将风格档案保存到：
   `~/.workbuddy/skills/prd-style-learner/profile/prd_style_profile.md`
   使用下方「风格档案模板」的结构。

5. 如果已有风格档案，进行增量合并（新样本补充而非覆盖）。

6. 告知用户学习完成，展示提取到的关键风格特征摘要。

### 模式二：write — 按已学风格写新 PRD

触发词：「按我的风格写PRD」「帮我写PRD」「写一份PRD」

**流程：**

1. 读取风格档案：
   `~/.workbuddy/skills/prd-style-learner/profile/prd_style_profile.md`
   如果档案不存在，提示用户先执行 learn 模式。

2. 与用户确认新 PRD 的主题和关键信息：
   - 产品 / 功能名称
   - 背景和目标
   - 核心功能点
   - 其他用户想强调的内容

3. 严格按照风格档案中的结构、章节命名、语气、格式偏好来生成 PRD。
   **不是套用通用模板，而是复刻用户自己的 PRD 风格。**

4. **跨领域适配（关键步骤）：** 对照风格档案第五节「跨领域适配规则」：
   - 保留：章节骨架、量化表达方式、星级优先级体系、用户画像三段式、
     数据全链条方法论、Callout 框用法、边界 Case 处理规则、多利益相关方视角
   - 替换：行业背景数据、具体技术指标、领域术语、对应法规——全部按新领域重新生成
   - 禁止：把已学样本中 A 领域的技术细节（如人脸识别的 FID、金融的 DCF）直接搬进新领域 PRD
   - 新领域的核心技术方案要写到与样本同等深度（用户写 PRD 的技术深度是恒定的）

4. 输出为 Markdown 格式（用户可后续转换为 Word）。
   如果用户需要 Word 格式，使用 tencent-local-office-edit 技能或 python-docx 生成 .docx。

### 模式三：update — 更新风格档案

触发词：「更新PRD风格」「补充学习新的PRD样本」

流程与 learn 模式相同，但会读取已有档案并增量合并。
learn 模式本身就是增量式的，update 只是为了语义上更清晰。

## 注意事项

- Word 文档解析使用 python-docx（已安装在 managed venv 中）
- PDF 解析使用 PyMuPDF/fitz（已安装在 managed venv 中），支持文本型和含表格的 PDF
- 扫描型 PDF（纯图片无文本层）解析脚本会提示无文本，需先用 OCR 工具处理
- 如果用户提供的是 .doc（旧格式），提示用户转换为 .docx
- 如果用户提供的是 Markdown 格式 PRD，跳过解析脚本，直接用 Read 工具读取全文即可
- 学习多份样本后，注意区分「PRD 类型结构变体」（如模型专项 PRD vs 产品级 PRD 含竞品分析/原型图），在档案中分别记录骨架，写作前先问用户要写哪种类型
- 增量合并时只把「跨样本共性」写入方法论，新样本的独特写法（如竞品五段式、痛点递进链）标注来源样本号后再纳入档案
- 学习多个 PRD 样本时，提取共性特征，同时记录差异（如不同类型 PRD 的结构变体）
- 风格档案是 Markdown 文件，人可读，用户可以手动编辑微调
- 写作时如果用户的某个 PRD 类型有多种结构变体（如「新功能PRD」和「优化PRD」结构不同），询问用户当前要写哪种类型
