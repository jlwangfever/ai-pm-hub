## 一、跨领域通用结构模板（写作骨架）

三份 PRD 共享同一套章节骨架，写任何领域的新 PRD 都按此组织：

```
1. 项目背景
   1.1 行业背景（宏观趋势 + 市场规模数据 + 政策引用）
   1.2 行业/技术演进阶段（用版本号划分时代：1.0→2.0→2.5→3.0）
   1.3 传统方案痛点（每条痛点配具体数字佐证）
2. 项目目标
   - 按场景拆分目标，每个目标配可量化指标
   - 用 ⭐️ 标记目标优先级
3. 需求分析
   3.1 功能性需求（模型需求 + 系统/后台需求 分开写）
   3.2 非功能性需求（性能、鲁棒性、安全隐私、可迭代性）
4. 技术调研 / 系统架构
   - 技术路线对比表格（多方案横向对比）
   - 架构分层设计 + 端云/模块协同策略
5. 核心方案设计（重头戏，标记 ⭐️⭐️⭐️~⭐️⭐️⭐️⭐️⭐️）
   5.1 场景/意图体系设计（MECE 分解 + 用户旅程映射）
   5.2 数据准备（采集渠道 → 处理流程 → 数据量级规划）
   5.3 数据标注（标注体系 + 标注规范 + 质控机制）
   5.4 模型训练（分阶段：预训练→微调→持续优化）
   5.5 模型评估（指标体系 + 评测流水线 + 评分机制）
   5.6 模型应用（推理服务 + Prompt 工程 + 结果加工）
6. 安全与合规（必须独立成节，引用具体法规名称和条款）
7. 参考文档（列出参考资料、链接）
```

**关键结构特征：**
- AI/算法类项目：需求分析中「模型需求」和「后台系统需求」分开两章写
- 数据链条完整：采集→增强→标注→质控→训练→评估→应用，全流程覆盖，绝不断链
- 前三份 PRD 均有独立的合规章节（人脸识别法规 / 汽车数据规定 / 金融监管）

## 二、写作风格 DNA

### 2.1 量化至上（最重要的特征）

**所有论述都带具体数字，绝不空谈：**

- 背景痛点：「年均制卡量达3.5万张，单张综合成本≥20元，高峰期排队超40分钟，投诉率同比上升37%」
- 模型指标：「1:1验证准确率≥99.9%，端到端延迟≤300ms，单节点≥100 QPS」
- 市场数据：「据亿欧智库预测，2030年市场规模将达66.1-75.3亿元」
- 用户调研：「92%的用户认为响应速度是TOP 3关键因素；34%在第三次失败后放弃使用」
- 数据规划：「训练集目标总计8万条；实车采集占60%、LLM增强占25%、众包占10%、回流占5%」
- 成本痛点（样本4）：「外包单张图500-2000元，年投入可达数十万」「返工率超40%」「GPU云实例峰值渲染成本较自建机房降低60%以上」
- 需求节奏（样本4）：「单项目平均需产出5-8个方向性方案」「78%的设计院将在未来两年内把实时渲染能力纳入标准工作流」

**写作规则：每个痛点、每个目标、每个结论都必须有数字支撑。**

### 2.2 版本演进叙事

用「版本号 + 时间段 + 特征 + 举例」四要素讲述行业/技术演进：

> 1.0：命令词识别（2015年~2018年）
> 特征：固定唤醒词和有限命令集（约50条），本质是"人适应机器"
> 举例：早期车载蓝牙语音系统，需精确说出"拨打电话给张三"

### 2.3 通俗比喻解释技术（教学化表达）

技术概念用「一句话概括 + 通俗理解 + 技术本质 + 技术特点」四段式：

- 「预训练就像让婴儿疯狂阅读互联网上所有书籍」
- 「微调就像送博学的大学生去医学院专业培训」
- 「RAG是给LLM配一个外置参考书——先查资料再作答」
- 「就像让AI上了个『人脸大学』，看过几百万张照片后知道『这是眼睛、那是鼻子』」

### 2.4 星级优先级体系（个人标志性用法）

**用 ⭐️ 数量（1~5星）标记章节/需求的重要程度：**

- 「5. 方案设计（⭐️⭐️⭐️⭐️⭐️）」— 全文最核心
- 「3. 人脸识别模型方案设计（⭐️⭐️⭐️）」— 次重要
- 「意图识别（Intent Detection⭐️⭐️⭐️）」— 标记需求项

### 2.5 多利益相关方视角

复杂技术决策用多视角表格呈现（谁负责/花多少钱/多久见效/风险点/老板关心）：

| 维度 | 阶段一：预训练 | 阶段二：微调 | 阶段三：持续优化 |
|------|---------------|--------------|------------------|
| 谁负责 | 算法团队 | 算法+数据团队 | 算法+运维+产品 |
| 老板关心 | "能不能用" | "准不准" | "稳不稳、省不省钱" |

### 2.6 用户画像三段式

用「人物A/B/C + 画像 + 核心场景 + 核心诉求 + 痛点」的标准格式：

> 人物A：白领工作者（核心用户）
> 画像：30-45岁职场白领，日均通勤1.5-2小时
> 核心诉求：快速、准确、零分心
> 痛点：需要说"导航到公司"而非"我去上班"，不够自然

### 2.7 五步法/阶段化方法论

复杂问题拆解为编号步骤，每步独立成节：

- 意图场景五步法：用户旅程映射 → 频次分析 → MECE分解 → 复杂度评估 → 优先级矩阵
- 模型训练三阶段：大规模预训练 → 场景微调 → 部署优化（每阶段配「关键要点」框）

### 2.8 边界 Case 显式处理

明确写出异常情况的处理规则，按优先级判定：

> 当一条语料可能匹配多个意图时，按以下优先级判定：
> 1. 安全优先：涉及行车安全的指令优先匹配
> 2. 确定性优先：精确指令优先于模糊指令
> 3. 单意图优先：先判断是否独立可执行
> 4. 域外兜底：无法匹配的归入 Bad Case

### 2.9 竞品五段式拆解（产品级 PRD 用，样本4验证）

每个竞品固定按五段展开，顺序不可变：

1. **产品定位**：一句带引号的口号定性，如「设计师的AI创意社区」「建筑设计师的AI渲染助手」
2. **核心能力**：维度/具体表现 两列表格（4行左右）
3. **典型应用场景**：3 个「场景名 + 一句话说明」的列表
4. **竞争优势**：3-4 条「标签式短语 + 冒号解释」
5. **核心短板**：短板/说明 两列表格

竞品拆完后必配三件套：**横向对比矩阵**（评估维度 × 竞品，用「极高/较高/中等/低」分档）→ **竞争空白与机会洞察**（空白地带/具体描述 表格）→ **差异化切入建议**（一句"比X更…比Y更…"的对仗式定位语）。

### 2.10 痛点→诉求→机会递进链（样本4强化）

痛点拆解表后紧跟两段收束叙事，形成「痛点 → 核心诉求 → 机会窗口」递进链：

> **核心诉求**：设计师群体呼唤"秒级响应、百元成本、零学习门槛、效果可控"的智能渲染解决方案…
> **机会窗口**：当前市场呈现"需求爆发但供给缺位"的特征：（列 3 条供给断层）…这一断层正是新产品切入的战略机遇期。

特征：诉求用**引号内四个短语并列**的口号式表达；机会窗口先给八字定性，再列竞品断层，最后一句战略收尾。

### 2.11 流程一行式（样本4新增）

简单的线性流程用反引号内箭头一行表达，不画图不编号：

`数据上传 → 数据预处理 → 训练配置 → 模型训练 → 模型评估 → 发布上线`

### 2.12 训练参数表格化（样本4强化）

LoRA/模型训练配置用四列表格：**参数类别 / 参数名 / 推荐值 / 说明**，参数类别列用合并单元格效果（类别名只在首行出现，其余留空）。推荐值写区间（如 16-128、1e-4 - 1e-3），说明列写一句通俗解释（如「矩阵秩，越大拟合能力越强」）。

### 2.13 NSM 方法论：候选排除 + 标准验证 + 反指标（样本5）

北极星指标章的固定三件套（全为表格）：
1. **候选排除表**：候选 NSM / 排除理由 / 危险 三列——排除理由写「A vs B」对比论证，危险列写「如果选它团队会怎么跑偏」
2. **7 项标准验证表**：标准 / 验证(Pass) / 说明——验证列居中对齐
3. **反指标体系表**：# / 反指标 / 黄线阈值 / 红线阈值 / 触发动作——危险项红线写「**立即暂停XX功能**」（加粗）

配套「商业游戏分类」定性开头（生产力游戏/注意力游戏/交易游戏，一句话给出可比产品），输入指标星座（5 个驱动指标 + 「MDEI 下降了，从 5 个输入指标定位根因」的故障排查逻辑）。

### 2.14 用户体验深度叙事三件套（样本5）

用户画像章升级为三个编号递进的深度研究：
1. **一日时间线表**（3.3.1）：时间 / 活动 / 情绪状态 / 使用工具 / 产品介入点 五列，从 06:30 到 18:00 逐时段展开；表后必有「**关键发现**：…最高价值的时刻不是X，而是让用户『有了原本没有的数据和能力』」式洞察句
2. **动机地图表**（3.3.2）：内在动机 / 强度(★1-5) / 产品如何满足 三列；表后「**洞察**：…都不是传统产品重视的维度」反转句
3. **反直觉洞察**（3.3.3）：加粗定性句（「信息的确定性比分数的绝对值更能降低家长焦虑」）+ 访谈细节展开 + 「这改变了产品的价值定位」收束

### 2.15 Model Story 场景叙事（样本5）

每个核心场景固定格式：`用户说："……"` 引号原文对话 → Agent 行为链（工具名内嵌的散文式描述）→ mermaid sequenceDiagram（participant + 箭头消息流，Note over 标注时间后效果）。复杂链路用编号代码块 Step 1-5 展开触发链路（每步缩进写检测→调用→数据流）。

### 2.16 失败模式/风险双目录（样本5，Pre-Mortem 方法论）

- **失败模式目录 FM-01~15 表**：编号 / 模式 / 严重度(🔴🟡) / 预防 / 概率×影响 / 老虎映射 / 恢复 Playbook（①②③编号步骤内嵌单元格）/ **乐观反驳**（「也许它不会发生，因为…」乐观视角列，个人标志性用法）
- **风险评估矩阵表**：风险 / 影响 / 缓解 / OST Score / 老虎映射 / 具体缓解步骤（①②③④）
- 「老虎」（Pre-Mortem 隐喻）编号 T1-T15，分四级：🔴 Launch-Blocking / 🟠 高优先级 / 🟡 Track / 🟢 观察

### 2.17 速查表模式 + 状态符号（样本5）

- **速查表**：`XX 速查` 是标志性命名（.env 配置速查 / 工具速查 / API 速查 / 数据库表速查），附录集中放 A-E 速查，正文冗长清单下沉到附录
- **状态符号**：模块状态 ✅ / ⚠️ N% / ❌ 0% / 🔄；严重度 🔴🟡🟢；优先级热度 ★1-5
- **生产信息入文**：API 地址、Key 环境变量名、真实文件路径、评测通过率（86/86）、人天数字全部写进 PRD——「与实际代码对齐」是活文档的核心特征

### 2.18 技术解释 blockquote（样本5，扩展 Callout 体系）

Callout 从单格表格扩展出引用块变体：`> **说明**：……`（用大白话解释技术机制，如「产品经理一般无需自己运行，CI 会自动执行并作为合入门禁」），穿插在代码块/配置块之前，专为非技术读者服务。

### 2.19 生命周期阶段拆解（业务分析方法，样本6 验证）

**核心用户有明确生命周期时，按生命周期阶段拆解需求：**

- 每个阶段固定结构：**时间范围 + 核心场景列表**（4-6 个核心场景）
- 例（样本6）：备孕 → 孕期（早/中/晚）→ 分娩与产后 → 新生儿（0-12月）→ 婴儿（1-3岁）→ 幼儿（3-6岁）
- 每个核心场景用"名词短语 + 一句解释"列表呈现，不展开技术细节
- 表后用 Callout 框收束该阶段的统一价值主张

**与现有档案的关系：** 是「用户画像三段式」（2.6）和「用户旅程映射」（方法论术语）的宏观补充——前者讲人物，中者讲旅程，本节讲业务时段。

### 2.20 大白话类比的"四段式结构 + 表格化对比"（样本6 强化 2.3）

在 2.3 的"一句话概括 + 通俗理解 + 技术本质 + 技术特点"基础上，强化为：

**单类比的四段式（强化版）：**
1. **通俗理解**：用生活场景打比方（"SD 就像一位博览群书的天才画家"）
2. **关键作用**：该技术在产品中扮演的角色（"它是基础画力担当"）
3. **类比内角色**：明确"它在我们产品里是干嘛的"
4. **> 💡 一句话**：类比收束句（"> 💡 **一句话**：SD 是'会画画的脑子'，但画的是路人甲"）

**多类比的表格化对比（新增）：**
- 当多个技术概念需要解释时，用三/四列表格对比收束：
  - 技术名 / 比喻 / 解决什么问题 / 如果没有它
- 表格前每个类比独立用四段式展开，表格做总览对照
- 例（样本6）：SD（天才画家）+ LoRA（参考小册子）+ ComfyUI（智能流水线工作台）

### 2.21 双维度标签模型（样本6 验证）

**分类体系不止按一个维度切，而用"X × Y"双维度交叉：**

- 维度1：场景类型（如：健康医疗 / 营养喂养 / 教育启蒙）
- 维度2：处理优先级（如：L1 危急 / L2 紧急 / L3 需观察 / L4 常规）
- 每个交叉点对应不同的系统动作和输出策略

**配套强制规则：** 紧急维度优先——L1/L2 触发时强制中断标准流程，跳到急救通道。

**与现有档案的关系：** 是「边界 Case 处理规则」（2.8）的体系化扩展——2.8 讲"边界怎么判定"，本节讲"先建分类再判定"。

### 2.22 C-A-R-E 结构化输出（AI 产品回答模板，样本6 验证）

**所有 AI 产品的输出答案强制遵循 C-A-R-E 四段式：**

| 字母 | 含义 | 强制要求 |
|---|---|---|
| **C - Conclusion** | 结论先行 | 一句话核心建议，必须出现在第一句 |
| **A - Action** | 具体步骤 | 1、2、3 编号步骤，每步可执行 |
| **R - Reason** | 循证解释 | "为什么这样做"，引用权威来源 |
| **E - Emergency** | 危险信号 | 紧急情况的触发条件和就医建议 |

**配套规则：**
- 每条建议必须携带"知识身份证"（来源 + 证据等级 + 免责声明）
- 高风险领域（医疗/法律/金融）必须强制 E 段，否则拦截
- 与样本5 的 Model Story 互补：Model Story 讲"对话剧本"，C-A-R-E 讲"单条回答结构"

### 2.23 混合检索策略双路并行（AI 系统架构，样本6 验证）

**RAG/搜索类系统的标准架构：**

```
用户查询 → BM25 关键词检索 ──┐
                            ├──→ 重排序模型 → 阈值过滤 → Top-K 答案
       → 向量语义检索 ──────┘
```

- BM25 负责精确匹配（关键词、专业术语、专有名词）
- 向量检索负责语义泛化（同义词、近义表达、口语化表达）
- 两条路并行，合并后用重排序模型（如 BGE-Reranker）排序
- 低于阈值的片段直接过滤

**适用所有 RAG 产品**：智能客服、文档问答、企业知识库、AI 助手。跨领域保留架构，替换具体检索对象。

### 2.24 意图分类与紧急识别双通道（AI 安全设计，样本6 验证）

**高风险 AI 产品（医疗/法律/金融/自动驾驶）的强制设计模式：**

- **双通道并行**：意图分类通道 + 紧急识别通道
- **紧急通道独立触发**：一旦识别 L1/L2 危急情况，立即中断标准流程
- **紧急通道的动作**：急救指引 + 紧急联系方式 + 最近的应急资源导航
- **强制不可绕过**：紧急通道优先级最高，不可被其他逻辑覆盖

**与现有档案的关系：** 是「边界 Case 处理」（2.8）和「双维度标签」（2.21）的安全强化版，强调"安全优先"是系统级硬约束。

### 2.25 知识库分层架构 T1-T4（数据治理方法，样本6 验证）

**需要权威性分层的知识库/内容库，按四层架构设计：**

| 层级 | 内容来源 | 权重 | 更新频率 | 标注要求 |
|---|---|---|---|---|
| **T1 权威指南** | 国际/国家权威机构 | 最高 | 季度更新 | 来源+版本+证据等级 |
| **T2 标准共识** | 行业共识/专家共识 | 高 | 半年更新 | 发布机构+日期 |
| **T3 平台知识** | 平台医学/专业团队 | 中 | 月度更新 | 审核人署名 |
| **T4 社区经验** | 双审通过的 UGC | 低（仅辅助） | 实时 | 明确标"经验分享，非专业建议" |

**适用场景：** 母婴、医疗、法律、金融、教育等所有需要权威背书的内容产品。检索时 T1+T2 优先，T4 仅作补充。

### 2.26 行业拐点叙事「三重突破 + 范式跃迁」（样本6 强化）

**写"行业背景"时，比 2.2 的版本演进叙事更宏观的写法：**

**结构模板：**
1. **技术融合的三重突破**（3 个并列子点，每点配 1 个数据 + 1 个产品案例）
   - 例：认知智能的垂直深化（95% 事实一致性 / 米卡育儿）
   - 情感计算的突破应用（LOVOT 拟真拥抱 / 心大陆行为习惯机器人）
   - 多模态交互的场景重构（0.3 秒响应 / 豆包 DeepSeek）
2. **传统模式的结构性困境**（3 个并列痛点，每个痛点拆 3 个子点，全部配数字）
3. **核心命题：「从 X 到 Y」的范式跃迁**（一句话定性 + 三重突破列表）

**与 2.2 的区别：** 2.2 用"版本号 1.0→2.0→3.0"讲技术演进；本节用"技术突破 → 传统困境 → 范式跃迁"讲哲学高度的转折，更适合做"开篇故事"。

### 2.27 占位章节约定（样本6 验证）

**未完成模块用一句话占位，避免"留白"歧义：**

- 模板：`#### 任务：完成 XX 智能体方案设计和实操演练`
- 占位行用 `####` 4 级标题，明确这是 TODO 不是遗漏
- 后续完成时直接替换这一行即可，保留目录结构
- 适合"多智能体方案书"的并行模块化场景

## 六、写作注意事项（生成新 PRD 时的检查清单）

1. ✅ 背景章节：宏观趋势有市场数据，痛点每条配数字，有政策/权威引用
2. ✅ 有演进阶段叙述（版本号 + 时间段 + 特征 + 举例）
3. ✅ 目标可量化（准确率/延迟/QPS/覆盖率的具体数值）
4. ✅ 模型需求和系统需求分开成章
5. ✅ 非功能需求覆盖：性能、鲁棒性、安全隐私、可迭代性
6. ✅ 技术方案有横向对比表格
7. ✅ 核心章节标 ⭐️ 星级（重头戏标 4-5 星）
8. ✅ 数据链条完整不断链：采集→增强→标注→质控→训练→评估→应用
9. ✅ 每个功能点/场景配典型示例（语料/数据/JSON 实例）
10. ✅ 复杂技术用通俗比喻 + 「⚠️关键要点」Callout 框解释
11. ✅ 有优先级矩阵和 P0/P1/P2 分期策略
12. ✅ 有边界 Case 处理规则（按优先级判定）
13. ✅ 独立合规章节，引用具体法规名称（模型专项 PRD 必须；产品级 PRD 至少在非功能需求中覆盖数据隐私，如 GDPR）
14. ✅ 关键决策有多利益相关方视角（谁负责/多少钱/多久见效/老板关心什么）
15. ✅ 结尾有参考文档列表（模型专项 PRD；样本4 的产品级课件版无此节，为可选项）
16. ✅ 产品级 PRD 必含：竞品五段式拆解 + 横向对比矩阵 + 竞争空白洞察 + 产品设计（架构图/原型图占位）
17. ✅ 痛点章节用「痛点拆解表 + 核心诉求口号 + 机会窗口断层分析」三连收束
18. ✅ 评估体系双轨制：自动化指标表（指标/评估方法/工具）+ 人工评估（盲测 A/B + 评分维度 + 众包）
19. ✅ Markdown 输出时图片用相对路径引用（如 `![image.png](图片和附件/xxx.png)`），并建同名附件目录存放
20. ✅ Agent 全生命周期 PRD（变体 C）必含：执行摘要（含 NSM 三件套）/ 硬性边界 / Model Story / 失败模式目录（含乐观反驳列）/ 评测三层架构 + CI 门禁阈值 / Phase 人天清单 / 增长章（OST/ICP/TAM-SAM-SOM/滩头阵地/已杀死方案）/ 附录速查 + 修订历史
21. ✅ 变体 C 用 mermaid（flowchart LR + sequenceDiagram）替代手绘架构图，技术机制前加 `> **说明**：` 通俗引用块
22. ✅ 量化数字贯穿全篇：效率对比（6h→27min，约94%）、采纳率、人天、市场规模、概率×影响——变体 C 中密度最高
23. ✅ 用户研究章含「关键发现/洞察」加粗收束句（最高价值不是替代手工，而是给了原本没有的能力）
24. ✅ AI 产品立项 + 多智能体方案书（变体 D）必含：业务生命周期阶段拆解（2.19）/ 行业拐点三重突破叙事（2.26）/ 知识库 T1-T4 分层架构（2.25）/ 双维度标签 + 紧急通道安全设计（2.21+2.24）/ C-A-R-E 输出模板（2.22）/ 多类比表格化对比（2.20）/ 占位章节约定（2.27）
25. ✅ 每个 AI 智能体独立成节，平行展开技术方案；实操教程外置为子目录链接
26. ✅ 大白话类比必带四段式（通俗 + 关键作用 + 类比内角色 + 💡 一句话）+ 多类比时用表格化对比收束
