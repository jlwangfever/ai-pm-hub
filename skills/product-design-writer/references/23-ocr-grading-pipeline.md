> 源文档：23-答题卡OCR批改系统设计.md

## 回答什么问题

非结构化文档/图片（答题卡、试卷、手写稿）怎么被解析、识别、批改并回流到业务链路？这是把物理输入转成结构化数据的「入口管线」。要设计的是一套可降级、可观测、有边界的识别-批改流水线，而非某个具体引擎的调用。

核心产出：端到端批改管线、UploadSession 状态机、多引擎文档解析兜底链、批量调度机制、LLM 批改引擎（答案来源三模式 + 两条执行路径 + 统一结果结构）。

## 怎么设计（框架/步骤）

### 1. 先定系统定位与「不在范围内」

明确它是上游入口，写清设计目标指标（效率/准确率/耗时）与**不在范围内**（如不做实时视频流、不做手写公式深度识别、不做跨主体对比），防止需求蔓延。

### 2. 端到端批改管线（10 步）

画管线图并配步骤表：每步给「触发条件 / 关键技术 / 预估耗时」。典型链路：批量上传 → 识别 → 信息提取 → 答案来源选择 → 语义批改 → 人工确认 → 保存 → 触发下游（诊断/统计/报告）。步骤表让工程可估算与排障。

### 3. UploadSession 状态机

定义会话全生命周期状态枚举：`UPLOADED → PREVIEWING → READY → IMPORTING/GRADING → IMPORTED/完成`，及 `DISCARDED`（用户取消）、`ERROR`（异常）终态。每个状态写清含义、触发转换的事件、此时可获取的信息。需含重试（失败回退上一态）与并发控制（乐观锁）。

### 4. 文档解析三引擎兜底策略

按文件类型自动路由，每条路径有多级降级链：

- **图片路径**：优先云端 OCR API（手写优化）→ 失败降级多模态 VLM → 仍失败返回部分结果（标记低置信度）
- **PDF/Office 路径**：优先本地解析引擎（免费、印刷体好）→ 失败转图片走 OCR → 仍失败降级 VLM
- **混合路径**：MinerU 与 OCR 并行，全失败才降级 VLM

原则：**优先本地免费引擎降本，云端高精度 API 做主力，VLM 做最终兜底**，任一失效互不阻塞。

### 5. 批量调度（轮询 vs 消息队列）

定义任务模型（状态 `pending→processing→done/failed`，失败可手动重试）与调度方式。MVP 可用状态表 + 定时轮询（实现简单、部署轻、延迟可容忍）；规模增长再迁移到 Celery/Redis，任务模型保持不变。**决策要写清理由**（简单性/调试/部署/规模）。

### 6. LLM 批改引擎：答案来源三模式 + 两条路径

- **答案来源优先级**：题库匹配（最高）→ 教师录入（中）→ 模型自判（最低，需人工复核）
- **执行路径**：专用批改 API（异步创建任务轮询）/ 通用语义批改（同步），两路汇成统一结果结构（逐题判定 + 汇总）
- 结果 JSON 落到字段：task_id、student_id、score、total、questions[{q_number, student_answer, correct_answer, is_correct, reason}]

### 7. 边界条件与错误处理

逐项写策略：识别失败（标失败+重试按钮）、不可读图片（partial+人工录入）、学号未匹配（跳过脏数据）、低置信度（标人工复核）、空批次（400/404）、服务未配置（启动自检三引擎状态）。脏数据保护：未注册主体的记录静默跳过，不阻塞批次。

## 文档结构

1. **系统定位与目标**：指标表 + 不在范围内
2. **批改管线**：10 步图 + 步骤表
3. **UploadSession 状态机**：状态枚举 + 转移 + 实体字段
4. **文档解析三引擎兜底**：路由图 + 降级链 + 引擎对比
5. **批量调度**：任务模型 + 轮询/队列决策
6. **LLM 批改引擎**：答案来源三模式 + 双路径 + 结果结构
7. **边界条件与错误处理**：6+ 类异常策略

## 及格线

- ☑ 有端到端管线图 + 每步触发条件/技术/耗时
- ☑ UploadSession 状态机含状态枚举、转移、重试、ERROR/DISCARDED 终态
- ☑ 文档解析有三引擎兜底 + 按文件类型的降级链（非单引擎）
- ☑ LLM 批改有「答案来源三模式」与统一结果 JSON 结构（字段明确）
- ☑ 写清「不在范围内」+ 至少 5 类边界错误处理策略

## 最易挂的坑

- **单引擎无兜底**：只接一个 OCR/解析服务，一旦限流或下线整条管线瘫痪；必须多引擎降级链。
- **状态机无失败态**：UploadSession/Task 只画成功流转，缺 ERROR/取消/重试，真实异常无法恢复。
- **脏数据入链**：未匹配主体的记录直接写入，污染下游诊断与统计；须静默跳过并标记。
- **调度选型过重**：MVP 就上消息队列，部署与运维成本抵消了早期速度；规模未到先用状态表轮询。
