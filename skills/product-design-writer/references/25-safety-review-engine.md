> 源文档：25-四维安全审核引擎设计.md

## 回答什么问题

凡是系统对外输出内容（AI 生成、用户对话、工具调用），哪些内容必须「零错误」、哪些可以「标记但不拦截」？这是内容安全的最后一道门。方法论价值在于：**把可确定判定的正确性交给确定性算法和规则库，而不是交给同一模型自检**。

核心产出：多维度独立审核框架、确定性算法硬红线（100%）、规则库软告警、统一审核报告结构、评测指标 + 确定性测试集 + 已知边界 Case 清单。

> 维度示例（中性）：一个内容安全引擎可拆为 D1 确定性正确性（数值/逻辑一致性）、D2 规则完整性（关键词/模式缺失检测）、D3 领域合理性（不合理产物/状态检测）、D4 格式规范（结构合法性、专业符号渲染）。具体维度由所属领域填充，方法不变。

## 怎么设计（框架/步骤）

### 1. 定位：放在「生成层」与「输出层」之间

任何产生待审内容的路径（出题、对话、工具）都必须经过审核。集成点用表登记：调用方、调用位置、拦截后行为（打回重生成 / 标记输出）。

### 2. 多维度独立拆分（互不依赖）

每个审核维度是独立的确定性算法或规则库，维度之间不互相调用、不依赖同一模型自检。典型四槽位：

| 维度 | 校验性质 | 结果级别 |
|------|----------|----------|
| D1 确定性正确性 | 可算法判定的数值/逻辑一致性（如元素原子计数法逐项比对） | **硬拦截**（100% 红线） |
| D2 规则完整性 | 关键词/模式规则库，检测缺失项（如必要条件未标注） | 软告警/失败 |
| D3 领域合理性 | 正则/规则检测不合理产物或状态 | 软告警/失败 |
| D4 格式规范 | 结构合法性：括号匹配、符号格式、领域专属渲染规范 | 软告警/失败 |

### 3. 确定性算法做硬红线，规则库做软告警

- **D1 必须 100% 通过**：用确定性算法（非 LLM），对任意正确格式输入给出确定性的正确/错误判断，不存在不确定空间。失败即 HARD BLOCK，打回重生成并告警。
- **D2/D3/D4 用规则库**：存在灰色地带，设召回率目标（如 ≥80%），缺失/不完美时 SOFT WARNING，标记但不拦截，计入质量统计。

### 4. 统一审核报告结构

每次审核产出 JSON：四维度各自 `{status, message, detail}`，加 `overall_status`（passed/blocked）。状态枚举：`passed / warning / failed / blocked`。综合判定：任一维度 blocked → 整体 blocked；否则 passed。明确区分「硬拦截（不可输出）」与「软告警（可输出但建议）」。

### 5. 服务接口与归一化前置

公开综合审核 + 单维度检查接口（输入内容串 → JSON 报告）。审核前需格式归一化（统一领域专属符号/箭头/上下标），确保算法可解析。

### 6. 评测指标 + 确定性测试集 + 边界 Case

- 指标表：每个维度定目标值与是否红线（D1 为 HARD RED LINE）。
- **确定性测试集**：覆盖全部典型情形，每例有唯一正确答案，通过标准如 86/86 全过；接入 CI 门禁，每次提交回归。
- **已知边界 Case 清单**：列出当前算法局限（如多步合写、非标准符号、需电荷守恒等），明确归属（算法不处理 → 交 LLM 补充或人工）。

### 7. 写「不在范围内」

明确本引擎不做什么（如不做深度语义判断、不覆盖某类反应、不替代 LLM 审核），防止越权。

## 文档结构

1. **系统定位与目标**：架构位置 + 指标表（含红线）+ 不在范围内
2. **多维审核框架**：四维度独立拆分表（性质/级别）
3. **各维度算法设计**：确定性算法步骤 + 规则库 + 示例
4. **审核报告结构**：JSON 字段 + 状态枚举 + 综合判定
5. **服务接口**：综合/单维检查 + 归一化前置
6. **评测指标 + 确定性测试集 + 已知边界 Case**

## 及格线

- ☑ 审核按「多个相互独立维度」拆分，维度间不依赖同一模型自检
- ☑ 至少 1 个维度用确定性算法并设 100% 硬红线（HARD BLOCK），其余用规则库软告警
- ☑ 有统一审核报告结构（每维度 status+message+detail + overall_status）
- ☑ 有评测指标 + 确定性测试集（唯一正确答案，CI 回归）+ 已知边界 Case 清单
- ☑ 写清「不在范围内」与硬拦截/软告警的区别

## 最易挂的坑

- **用 LLM 自检 LLM**：让生成模型同时做正确性校验，错误会被自我确认；可确定性判定的正确性必须交给确定性算法。
- **只有软告警没有硬红线**：所有维度都「建议」不拦截，零错误的红线内容照样输出，安全底线失效。
- **无确定性测试集**：审核准确率口说无凭，没有唯一正确答案的回归集，CI 无法守住红线。
- **维度互相依赖**：某维度调用另一维度或共用一个不确定模型，单维度失败无法隔离，难定位难维护。
