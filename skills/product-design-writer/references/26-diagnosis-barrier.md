> 源文档：26-错题诊断与障碍分类系统设计.md

## 回答什么问题

「谁错了」是结果统计，「为什么错」是根因诊断。诊断/障碍分类系统要解决的是：把一次错误作答归因为少数几种**可枚举的障碍类型**，输出学生级障碍画像，并向下游（练习、复习、预警）提供结构化的干预依据。它是「诊断—干预—巩固」闭环的第一环。

核心产出：障碍分类模型 + 混合判定管线 + 置信度分级 + 人工覆盖入口 + 单生→班级聚合。

## 怎么设计（框架/步骤）

**1. 先建可枚举的障碍分类模型（这是地基）**
- 障碍类型必须相互独立、可穷举，例如「概念理解型 / 审题障碍型 / 表述障碍型」三维度。维度来源于该领域的认知特点，而非拍脑袋。
- 学生级画像存为占比 JSON（各类型之和为 1.0），便于排序出「主导障碍」；每次错误主因归入一类，但允许一人同时存在多类（用占比体现）。
- 核心指标须先定义：诊断覆盖率（被诊断覆盖的错误作答占比）、高置信度占比、教师复核通过率、诊断延迟（如 <30s/班）。

**2. 三段式混合判定管线（规则 + LLM）**
- 规则引擎初筛 → LLM 深度语义分析 → 综合判定。规则做低成本初筛（置信度控制在 0.5–0.7，避免过度自信），命中/未命中均进入 LLM；LLM 输出结构化 JSON（类型 + 置信度 + 判定依据 + 干预建议）。

**3. 置信度三级分级与处理策略（必做，否则不可信）**

| 置信度区间 | 级别 | 处理策略 |
|-----------|------|---------|
| ≥ 0.8 | 高 | 自动采纳，直接写入 |
| 0.7–0.8 | 中 | 采纳但标注「需关注」，聚合时降权 |
| < 0.7 | 低 | 标记「建议人工复核」，前端开放覆盖入口 |

**4. 留 human-in-the-loop 覆盖入口（必做）**
- 教师可手动推翻 AI 判定：记录旧画像 + 新画像 + 覆盖原因到日志；覆盖后在下一次诊断前保持不变，新作答数据回流后逐步稀释覆盖权重。

**5. 教师自定义配置**
- 触发阈值、掌握判定阈值、是否自动同步给学生等可配置（不同使用者敏感度不同）。

**6. 数据写入链路与聚合**
- 统一事务提交后再做聚合；Aggregation 时补全缺失类型键为 0，保证画像 JSON 始终含全部键。
- 单生诊断 → 班级分布聚合（每次考试后自动更新）。

**7. 闭环位置**
- 上游：作答结果写入；本系统：障碍判定+画像；下游：自适应练习（按障碍类型匹配难度/题型）、学习计划生成。

**8. 触发时机与可解释性**
- 触发分批量（教师点选考试后跑）、近实时（提交后异步）、手动覆盖、Agent 工具调用四类；批量应设单次处理上限（如 10 条）+ 并发上限（如 5 线程）防 LLM 过载。
- 每个诊断结果必须可解释：返回置信度分布 + 判定依据 + 干预建议，前端按主导障碍占比用颜色标记严重度（如 ≥60% 红 / 40–60% 黄 / <40% 绿）。

**9. 教师自定义阈值（示例，中性化）**
- 各类障碍的「连续错误 N 次触发诊断」「连续答对 N 次视为掌握」「是否自动同步给学生」均可配；不同使用者敏感度不同（资深者可调低概念类阈值更早警觉）。

## 文档结构

1. **系统定位**：差异化价值（从结果统计→根因诊断）、设计目标表、核心指标（诊断覆盖率/高置信度占比/教师复核通过率/诊断延迟）、在闭环中的位置、不在范围内功能
2. **障碍分类模型**：枚举值表（名称/核心特征/典型表现）、分类依据、数据模型（画像字段）
3. **诊断流程**：架构图（规则→LLM→综合）、API 调用路径、触发时机表、接口 Schema
4. **规则引擎**：关键词/模式库、局限性（降级方案）
5. **LLM 诊断 Prompt**：输入结构、System/User 模板、输出 JSON 规范、调用参数（低温度、并发、事务一致性）
6. **置信度分级**：三级表 + 聚合计算步骤
7. **配置 / 覆盖机制 / 写入链路 / 班级聚合 / 前端 / Agent 工具 / 错误处理**

## 及格线

- ☑ 障碍类型可枚举、相互独立，并有「为何是这几类」的依据
- ☑ 采用规则+LLM 混合判定，且明确各自的职责边界与降级关系
- ☑ 有置信度分级（阈值 + 对应动作），低置信度有「人工复核」出口
- ☑ 有教师/专家人工覆盖机制并记录原因到日志
- ☑ 画像聚合逻辑定义清晰（含缺失键补全、统一提交时机）

## 最易挂的坑

- **把 LLM 当唯一判官**：无规则兜底、无置信度分级，低质量判定直接落库，无法解释也无法复核。
- **障碍类型互相重叠**：分类维度未正交（如「审题」与「概念」交叉），导致画像占比无法排序、下游无法用。
- **覆盖机制无日志/无稀释**：人工推翻后永久写死，新数据无法把权重拉回，画像逐渐失真。
- **置信度不持久化**：只存类型不存置信度，无法做「低置信度批量需复核」的二次筛查，聚合也只能用计数均值而非置信加权平均。
