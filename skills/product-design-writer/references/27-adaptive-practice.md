> 源文档：27-自适应练习引擎设计.md

## 回答什么问题

诊断告诉你「错在哪」，自适应练习帮你「改过来」。自适应练习引擎消费诊断产出的障碍类型、薄弱知识点和近期正确率，为每个学生生成**恰好落在最近发展区（ZPD）**的个性化练习题——太简单是浪费、太难会习得性无助。它是「诊断—出题—练习—反馈」闭环的「行动」环节。

核心产出：能力估计（ZPD）→ 目标区间 → 策略矩阵 → 参数计算 → 闭环回收。

## 怎么设计（框架/步骤）

**1. 能力估计：ZPD 难度计算**
- 用近 N 条作答记录算正确率，按区间映射难度档（如 easy / medium / hard）。区间含义比阈值本身重要：正确率过低需降级建立信心，过高需升级挑战。
- 样本窗口要有理有据（如 30 题）：过小会剧烈震荡，过大平滑掉近期进步。
- **冷启动默认中档（medium）而非 easy**：一次练习的代价即可完成自适应校准，避免对新生过度低估。
- 核心指标须先定义：ZPD 命中率（出题难度与实际水平匹配率）、练习完成率、进步率、出题响应时间（如 <30s/5 人）。

**2. 障碍类型 → 策略矩阵（核心差异化）**
- 按主导障碍类型决定：难度偏移、知识点选择倾向、题型配比。例如概念型降难度+增辨析题；审题型保持难度+增「陷阱」题；表述型保持难度+增需完整过程的题。

| 障碍类型 | 难度策略 | 知识点策略 | 题型策略 |
|----------|---------|-----------|---------|
| 基础概念型 | 降难度、聚焦基础 | 基础性知识点 | 增加辨析/填空 |
| 理解偏差型 | 保持 ZPD | 混合、不限定 | 增加「陷阱」/推断 |
| 表达规范型 | 保持 ZPD | 侧重需完整输出 | 增加需写过程/计算 |

**3. 出题参数计算流程（链路化）**
1. 读学生画像（主导障碍 / ZPD 档位 / 薄弱知识点 Top N）
2. 定知识点（薄弱点优先，教师指定兜底）
3. RAG 检索同类素材作参考（失败则纯生成）
4. 定题型（初始可统一题型，后续按矩阵展开）
5. 调 LLM 出题（知识点/难度/数量/题型/RAG 上下文）
6. 解析并写入题目与练习记录
7. 异步回流诊断数据

**4. 闭环回收与效果追踪**
- 学生提交→批改→后台异步诊断→更新画像→反映在下一次 ZPD。
- 效果追踪至少做「基础级」（两次练习正确率对比）：进步率 >0.1 显著、0~0.1 微调、<0 退步需重诊断。进阶做知识点粒度与难度档位流转图。
- 批次限制 + 失败隔离：每批限量学生（如 5 人），单点故障影响范围可控。

**5. 错误回退（保证不空手）**
- LLM 出题失败 → 从题库随机抽同知识点题兜底；薄弱点列表为空 → 用教师指定知识点；RAG 检索失败 → 纯 LLM 生成（不注入参考）。
- 预览态（如 Agent 对话中）不写库，确认后才持久化，避免预览改变学生画像。

## 文档结构

1. **系统定位**：ZPD 核心理念、设计目标表、核心指标（ZPD 命中率/完成率/进步率/响应时间）、不在范围内功能
2. **ZPD 模型**：输入参数、难度计算（窗口/三档/冷启动）、薄弱点提取、主导障碍识别、输出参数
3. **设计决策**：窗口取值、冷启动默认、批次上限的依据
4. **策略矩阵**：总表 + 题型×障碍完整设计（可分期启用）
5. **出题参数计算流程**：7 步 + 批次限制
6. **闭环逻辑**：流程图 + 关键点（实时/近实时/下次出题）
7. **效果追踪**：API、进步率判定、层级升级设计、前端状态机、错误处理、权限

## 及格线

- ☑ 有明确的能力估计方法（样本窗口 + 难度档映射 + 冷启动策略）
- ☑ 有「障碍类型×难度×知识点×题型」的策略矩阵，而非一刀切出题
- ☑ 出题参数计算是端到端链路（含 RAG 兜底、写入、回流）
- ☑ 闭环回收机制定义清楚：练习结果如何回到画像与下一次出题
- ☑ 有可量化的效果追踪与进步率判定标准

## 最易挂的坑

- **冷启动给 easy**：隐式假设「新用户什么都不会」，既不符合实际又伤害体验；medium 起点更稳。
- **ZPD 与障碍诊断强耦合**：ZPD 用实时正确率、障碍用异步 LLM 诊断，应解耦（不互相等待），否则实时性塌掉。
- **无失败隔离**：全班一次性出题，单题 LLM 格式异常导致整批失败。
- **效果追踪只比正确率**：题量/难度不同则对比失真，也无知识点粒度，看不到「假性掌握」（低难度高正确率但升级后骤降）。
