> 源文档：28-间隔复习与错题强化训练系统设计.md

## 回答什么问题

「学过的知识怎么不流失」靠两类互补机制：**间隔重复**（被动系统，到时间自动提醒巩固长期记忆）与**错题强化**（主动系统，学生打开错题本主动重练消除当前盲区）。二者可同时作用在同一道题上。复习系统是「诊断—练习—巩固」闭环的收口，把薄弱点从短期记忆转长期记忆。

核心产出：掌握度分级模型 + ReviewTask 状态机 + 升降级规则 + 同步去重 + 调度推送。

## 怎么设计（框架/步骤）

**1. 掌握度分级模型（螺旋间隔）**
- 用 N 级模型（如 6 级），每级对应一个复习间隔，间隔**指数增长**（1→3→7→14→30 天）——符合遗忘曲线（初期衰退最快）。
- 升级封顶后清空下次复习时间，引擎检测该状态即标记「已掌握」。
- 新建任务第 0 级立即可做（趁热打铁），真正等待从第 0→1 级才开始。

**2. ReviewTask 状态机（状态枚举 + 转移条件必须写实）**

| 状态 | 进入 | 退出 |
|------|------|------|
| 待复习 | 新建/完成复习后 | 超期；级别达上限→已掌握 |
| 超期 | 下次复习时间已过未做 | 补做→待复习 |
| 已掌握 | 级别达上限或人工标记 | 终态 |

- 超期任务仍可被查出补做，不因一次错过永久排除。

**3. 升降级规则（防偶然波动）**
- 升级：连续答对达 2 次 → 级别+1（上限封顶），连续正确计数归零。
- 降级：答错且级别>0 → 级别-1；级别=0 保底不降。
- 维持：单次答对不足 2 次不升级（一次答对不证明稳固）。
- 一次回退（上次对本次错）不降级，可能只是粗心。

**4. 同步机制（答题错→自动建任务）**
- 作答错后自动触发，遍历最近错误记录，按 `student_id + 题目_id` 去重，同一题最多一个任务，多次同步幂等。

**5. 错题强化子系统**
- 变式题原则：**同知识点、同难度、不同题面**（改数据/情境/选项），默认生成 3 道，防机械背答案。
- 「标记已掌握」等价告诉系统「不再推给我」：有 ReviewTask 则置 done，无则建 level=5 done。

**6. 每日推送调度器（Cron）**
- 每天固定时刻为每生生成今日练习（去重：日期+学生+类型），为绑定家长发通知，检查到期复习发提醒。
- **关键参数**：复习日期基准 = 当前时间 + 间隔天数（非「上次复习日 + 间隔」），每次完成以当前时刻重算。

**7. 降级与幂等**
- 同步时学生/题目不存在 → 跳过并记录 sync_errors；变式题 LLM 失败 → 返回原题 + 提示重试。
- 每日练习去重冲突 → 返回已存在记录（幂等），不重复建。

## 文档结构

1. **系统定位**：两子系统对比表（定位/触发/机制/目标）、设计目标、核心指标、不在范围内功能
2. **掌握度模型**：级别定义表、设计原理、首次创建行为
3. **状态机**：数据模型、迁移图、三状态含义表、到期查询逻辑
4. **升降级规则**：规则总表 + 判定逻辑 + 场景推演
5. **同步机制**：自动路径、触发点、去重
6. **到期复习与反馈**：到期判断、角标排序、反馈文案
7. **错题强化**：数据模型、列表获取、变式题、训练流程、API、标记已掌握
8. **前端 / 每日调度器 / 工程参数 / 集成边界 / 错误处理 / 权限**

## 及格线

- ☑ 掌握度分级模型有级别定义 + 指数间隔 + 封顶逻辑
- ☑ ReviewTask 状态机枚举完整，含超期补做与终态转移条件
- ☑ 升降级规则防偶然波动（连续答对才升级、保底、回退不降级）
- ☑ 同步去重（student+题目）保证幂等，不重复建任务
- ☑ 调度器有去重与「当前时间+间隔」基准定义

## 最易挂的坑

- **升级门槛太低**：单次答对就升级，随机运气导致任务过早关闭，知识未真正巩固。
- **间隔用「上次复习日」重算**：应每次以当前时刻为基准，否则补做/中断会累积漂移。
- **被动与主动系统打架**：错题强化「标记已掌握」必须同步回写 ReviewTask，否则两系统状态不一致。
