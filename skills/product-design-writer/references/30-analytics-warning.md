> 源文档：30-学情分析与预警系统设计.md

## 回答什么问题

学情分析是「数据可视化中枢」：消费批改、诊断、练习等上游数据，聚合成教师可直观理解的统计视图，并在数据异常时**主动**推送预警。它要让教师从「翻一堆原始记录」变成「一眼看到谁需要介入、哪个知识点全班薄弱、最近教学有没有效」。

核心产出：三维分析模型 + 量化指标定义 + 班级/学生视图 + 三类预警规则 + 调度引擎。

## 怎么设计（框架/步骤）

**1. 三维分析模型（知识点 × 学生 × 时间 立方体）**
- 三个切面各回答一个问题：知识点×学生=个体薄弱点定位；学生×时间=个人成长曲线；时间×知识点=教学干预效果。三轴交汇=班级全景。
- 核心指标须先定义：面板加载时间、预警及时性（异常到生成 <5min）、预警覆盖率（>95%）、误报率（目标 <10%，由人工确认消除）。
- 每个切面配对应 API，前端面板 = KPI 卡 + 图表 + 重点关注列表。

**2. 核心指标必须有数学定义（可复算、可对比）**
- 错误率：`errors(kp,c) / total(kp,c)`，分母为 0 时标注「暂无数据」不排名。
- 跨班可比：障碍分数按班级最大值归一化，消除批次间偏移。
- 班级均分用**指数衰减加权**（近期权重高，如一周前权重衰减 50%），对近期教学敏感又不被单次异常拖垮。

**3. 班级学情面板 + 学生详情抽屉**
- 面板：4 张 KPI 卡（考试次数/需关注/人数/均分）+ 知识点错误率 Top8 柱状图 + 障碍分布环形图 + 成绩趋势折线 + 重点学生横条（按障碍严重度 Top5）。
- 抽屉：学生 KPI + 障碍条形图 + 薄弱点标签云 + 最近活动 timeline；两步加载（缓存即时渲染 + 异步补详情）。

**4. 学情预警引擎（三类规则 + 级别 + 去重）**

| 类型 | 检测规则 | 级别判定 |
|------|---------|---------|
| 连续未活跃 | 距上次使用 ≥ 阈值天 | 固定 warning |
| 成绩下滑 | 最近两次均分降幅 | 降≥10% warning / ≥20% critical |
| 高错误率 | 最近一次错误数/总题数 | ≥50% info / ≥70% warning |

- 阈值遵循「**宁可误报不可漏报**」，人工确认环节消除误报。
- 重复预警去重：同学生+同类型+仍 pending 则不重复创建。

**5. 预警处理生命周期**
- pending → processed（记处理人/时间/备注）/ ignored；通知链查活跃绑定关系推送给相关方。

**6. 调度系统（APScheduler）**
- Cron（每日练习 08:00、预警检查 00:00）+ Interval（OCR 轮询 5s），启动时注册、关闭时优雅终止。
- 异常班级识别：连续多周低于年级基准线超阈值 → 标记「需关注」并推年级组长。
- 跨班级知识点对比矩阵（知识点×班级热力图）：某知识点在**所有**班级都是红色，说明是教学内容/教材问题而非某班教学问题，需教研组级介入。

## 文档结构

1. **系统定位**：架构位置、设计目标、核心指标、不在范围内（不排名/不绩效/不预测）
2. **三维分析模型**：立方体图、三切面表、指标数学定义
3. **班级面板**：布局、KPI 卡、三图表、重点学生横条、数据流
4. **学生详情抽屉**：布局、加载流程、各模块、交互
5. **数据分析 API 全景**：/api/panel + /api/analytics 端点清单
6. **预警引擎**：架构、三类规则表、阈值依据、数据模型
7. **预警处理流程 + 调度系统 + 前端 + 错误处理 + 权限**

## 及格线

- ☑ 分析模型是「维度×维度」立方体，每个切面有明确问题与 API
- ☑ 核心指标有可复算的数学公式（含分母为 0 处理、跨批可比方案）
- ☑ 预警规则有类型 + 检测逻辑 + 级别阈值 + 去重，阈值有「为何取此值」依据
- ☑ 预警有完整生命周期（生成→通知→处理/忽略）与调度触发点
- ☑ 权限边界清楚（教师可见、学生/家长不可看对比与原始数据）

## 最易挂的坑

- **指标无定义**：错误率/均分口径模糊，前端与后端对不上，跨班不可比。
- **阈值拍脑袋**：未说明依据，误报率过高淹没真预警或漏报真风险；应遵循「宁可误报」。
- **预警不收敛**：缺 pending 去重，定时任务每次全量扫描重复建预警，教师被刷屏。
- **面板耦合单数据源**：三路并行 API 任一失败即整页崩；应部分展示 + 失败模块给重试，单图表失败不影响其他。
