> 源文档：31-评测体系设计.md

## 回答什么问题

评测体系是 AI 产品的**质量基础设施**，回答四个问题：能不能发（发布门禁）、变好还是变差（趋势）、下一步开发什么（指导迭代）、处于什么水平（对标）。传统「功能测试清单」只能覆盖确定性能力，评测体系还要覆盖「语义质量」与「静默退化」。

核心产出：分层评估模型 + 快/慢双层运行 + 门禁策略 + 判官库 + 评估先行 + 黄金场景 + 性能预算。

## 怎么设计（框架/步骤）

**1. 七层评估模型（L0–L6，每层一个独立机制与节奏）**

| 层 | 评估什么 | 机制 | 轨道 |
|:---:|---------|------|:---:|
| L0 | 工具自身正确性 | 确定性断言 | 快 |
| L1 | 行为轨迹（工具/参数/顺序） | 黄金场景断言 | 快 |
| L2 | 输出与交互质量 | LLM-as-judge + rubric | 慢 |
| L3 | 安全护栏 | 对抗语料 + 断言 | 慢 |
| L4 | 性能预算（延迟/token/循环） | 阈值断言 | 快 |
| L5 | 稳定性回归 | 快照对比 | 快 |
| L6 | 端到端任务 | 场景剧本 | 慢 |

- L0/L1 是能力地基（零成本、每次必跑）；L2/L3 是质量与安全（花 token）；L4/L5 防退化；L6 业务验证。

**2. 快/慢双层运行 + 门禁**
- 快跑层（每次提交/CI）：零 LLM 成本秒级，**100% 必须绿**，任一确定性失败阻止合并。
- 慢跑层（夜间/发布前）：花 token，**严重错误一票否决**；判官分数只做趋势、不拦发布（分数有噪声，会误伤）。

**3. 评估先行（eval-first）+ expected_fail**
- 先写评估（定义「什么算好」）→ 此时全红，用 `expected_fail` 标记豁免不挡门禁；开发到绿后移除标记转常驻。绿→红的过程即进度指标，且不养「默默变绿仍在豁免」的死标记。

**4. 判官库（五族 rubric，最关键也最易踩坑）**
- 五族：出题/判卷/诊断/方案/交互智能；评分契约 = 分数 + 置信度 + 理由 + severe_flags。
- **判官与主模型解耦**（用备选 provider，避免自评偏差），上线前实测判官能力。
- **校准门槛 80%（族粒度）**：每族 20–30 条人工标注，判官 vs 人工一致率 ≥80% 才自动计分；不达标走「判官+人工复核」人机混合。启用决定在族粒度，非全局开关。
- 成本硬上限（如单次 200 次判官调用），超截断标注「未测样本」。

**5. 黄金场景体系（输入 + 期望行为断言）**
- 断言类型：工具调用（called/not/contain/count/order）、行为结果（no_error/text_contains/interrupt/route）、稳定性（set/order/hash stable）、SSE 契约（present/order/fields）。

**6. 性能预算 L4（软阈值 SLO 起步）**
- 单轮延迟 p95 ≤60s、单次 token ≤40k、循环 ≤12 轮；先 warn 不拦门禁，随数据积累逐步收紧。

**7. 报告与趋势**：按时间戳归档，未实现层如实标「未实现」不充 100%；判官调用次数 + 预估费用入成本台账。

**8. 已知缺陷管理**
- 已修复缺陷在回归维度统一登记（描述/发现修复日期/角色），防复发；已知架构缺口单独登记并标严重度与整改建议。
- 落地基线应可量化：单测项 + 快跑用例数 + 启用族一致率，作为演进参照。

## 文档结构

1. **评测定位**：四目标、三分法 vs 七层
2. **七层模型**：分层表 + 层间关系
3. **快/慢双层**：轨道表 + 运行器设计（层注册表/空层占位/趋势/成本）
4. **门禁策略**：两级 + expected_fail + 覆盖诚实
5. **判官库**：五族 rubric + 设计要点（解耦/校准/人机混合/成本/与门禁关系）
6. **eval-first 工作流 + 黄金场景 + 性能预算 + 报告趋势 + 执行验收 + 设计决策记录**

## 及格线

- ☑ 评估分层（离线单测→行为轨迹→语义质量→安全→性能→回归→端到端）且层间不互相替代
- ☑ 快/慢双层运行，快跑 100% 绿、慢跑严重错误一票否决，分数不进门禁
- ☑ 有 eval-first + expected_fail，评估可先于开发落地且不养死标记
- ☑ 判官与主模型解耦，校准门槛在族粒度（≥80%），低置信走人工复核
- ☑ 黄金场景有断言类型体系，性能预算为软 SLO，覆盖诚实（未实现不充数）

## 最易挂的坑

- **慢跑层用分数门禁**：LLM 打分有噪声，误杀正常发布；改为「严重错误一票否决 + 分数仅趋势」。
- **判官用被评同模型**：自评偏差，分数虚高；必须用备选 provider 并实测校准。
- **覆盖不诚实**：未实现层填 0/0 冒充 100%，掩盖真实盲区。
