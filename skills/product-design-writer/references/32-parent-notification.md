> 源文档：32-家长端与通知系统设计.md

## 回答什么问题

家长端是三端架构中**低频但高价值**的触点：家长不参与日常教学，但需了解子女状态（变化/薄弱/教师反馈）。系统要在「不制造焦虑、保护隐私」的前提下，用通俗语言把专业数据转译为家长能行动的信息，并通过可靠的通知通道送达。

核心产出：角色定位与四原则 + Tab 结构 + 绑定授权 + 数据权限模型 + 周报 Prompt 设计 + 通知渠道/类型/降级。

## 怎么设计（框架/步骤）

**1. 角色定位与四原则**
- 低频（月均 2–4 次）、移动端优先（窄屏 430px）、不排名不比较。
- 四原则：**不制造焦虑**（无排名/无负面词）、**通俗易懂**（专业术语→日常用语）、**可操作建议**（每条报告附 1–2 条家庭配合）、**隐私保护**（仅绑定子女、无原始试卷）。
- 核心指标须先定义：绑定完成率（>80%）、月活跃率（>40%）、周报打开率（>50%）、通知延迟（预警到送达 <10min）。

**2. 页面与 Tab 结构**
- 概览（统计卡 + 学习特点通俗版 + 动态时间线）/ 学习报告（掌握概览表 + 特点分析 + 家庭建议 + AI 解读）/ 消息（通知列表，已读未读）。
- 浮动 AI 助手：预设 5 个引导问题，SSE 流式覆盖层。

**3. 绑定流程（学生发起授权）**
- 绑定码机制：6 位随机数字，每个学生同一时刻仅一个有效码，重新生成旧码失效。
- **必须由学生端生成并分享**（非家长搜索学生），体现「学生授权家长查看」的数据最小化模型；绑定后可解绑。

**4. 数据权限模型（每次查询前置校验）**
- 权限链：机构→年级→班级→学生→绑定关系→家长。所有查子女数据的接口先查 `绑定关系(student_id, parent_id, status=active)` 三者匹配，否则 403。
- 可见/不可见清单明确：练习量/薄弱点/建议可见；原始答题/排名/其他学生不可见。

**5. 周报生成 Prompt 设计（转译是关键）**
- System Prompt 强约束：不提排名/不负面词、术语转换表（专业词→日常语）、先肯定进步再给 1–2 条建议、字数区间、温暖鼓励语气、无数据不编造。
- 输出 JSON 结构化（summary/detail/advice/no_data），长度约束；家长友好语言规则（数字→感受、知识点→主题、障碍→行为描述）。

**6. 通知渠道与类型（定义优先级、降级与静默）**
- 渠道：系统内通知（主）+ 外部（钉钉/企微/LTI/SFTP，按对接情况启用）+ Webhook 事件回调。
- 类型按 `type` 区分，带优先级：周报/计划/每日报告（普通）、学习提醒（警告）、成绩预警（警告/紧急）。
- 降级与静默：系统内失败直报；Webhook 失败入重试队列；同一周每生仅一份周报（去重），避免刷屏。
- 渠道选型权衡（移动 Web vs 小程序）：低频场景优先即用即走的移动 Web，覆盖 100% 设备、免下载、通知更灵活，且不阻塞未来接小程序。

## 文档结构

1. **系统定位**：架构位置、设计目标、核心指标、目标用户、四原则、数据权限模型、不在范围内
2. **页面**：登录页 + 主页面 3 个 Tab + 浮动 AI 助手
3. **绑定流程**：绑定码序列图、特性（6 位/单有效/可解绑）
4. **数据权限**：校验实现、可见/不可见清单
5. **周报 Prompt**：System/User 模板、变量表、输出约束、触发时机与去重
6. **通知渠道 / 通知类型 / LMS 集成（抽象基类+连接器+Webhook）/ 设计决策（码长度/学生发起/移动Web）/ 错误处理**

**附：关键 API 端点清单（中性化）**
- 绑定：生成绑定码 / 绑定（校验码+active 关系）/ 解绑 / 子女列表。
- 报告：子女概览 / 周报（自动+手动生成，周级去重）/ AI 解读。
- 通知：列表（分页）/ 标记已读；预警触发后写入通知表。
- 集成：LMS 配置读写 / Webhook 注册·测试·注销。

**附：设计决策需记录依据**
- 绑定码 6 位（4 位易被暴力枚举、8 位输入体验差）；学生发起授权（符合数据最小化）；移动 Web 而非小程序（低频场景即用即走、覆盖全设备）。

## 及格线

- ☑ 角色四原则落地（不焦虑/通俗/可操作/隐私），且有「术语转换表」支撑通俗化
- ☑ 绑定是「学生发起授权」而非家长搜索，权限链每次查询前置校验
- ☑ 数据可见/不可见清单明确，无跨生访问路径
- ☑ 周报 Prompt 有 System 约束 + 结构化输出 + 无数据不编造
- ☑ 通知有类型×优先级定义，及失败降级/静默/去重规则

## 最易挂的坑

- **家长直接搜索绑定**：产生大量越权请求与隐私投诉；必须学生生成绑定码授权。
- **周报堆砌术语与排名**：违背「不制造焦虑」，引发家长反弹；需术语转换表 + 先肯定后建议。
- **通知无降级无去重**：外部通道失败丢失、定时任务重复推送刷屏；需重试队列 + 周级去重。
- **周报生成 LLM 直接落库**：生成失败无重试、无「生成中」态，家长端看到报错；应后台重试 + 缺数据提示，绝不编造内容。

**通知触发链（中性）**：预警/周报/计划等事件 → 查活跃绑定关系 → 逐绑定推送；教师端走主动查询列表，家长端走消息 Tab，二者解耦互不阻塞。
