# 38 前端页面设计规格写作框架

## 回答什么问题

当一个端（教师/学生/家长）要落地成真实页面时，每个页面「长什么样、有哪些组件、各种状态下怎么表现、页面之间怎么跳转传参」必须被集中、无歧义地规定。本文档是设计系统（视觉规范）到代码之间的「组件级施工蓝图」——原型生成与前端开发都照它打勾。

## 怎么设计（框架/步骤）

按「端 → 页面 → 五要素」三层组织。所有页面共用一份设计系统，故文档开头引用设计系统，正文只描述**组件**不重复视觉细节。

**生成方法论：展开，不发明。** 本文档是从上游「展开出来的，不是写出来的」：输入 = 信息架构的组件表（逐页组件清单与数据依赖）+ 设计系统 + 页面流程；要求 = 逐页按五要素展开；**组件 MUST 来自信息架构组件表，禁止发明上游文档里没有的组件**；视觉引用设计系统；状态处理 MUST 三态全覆盖。产出后按四问审校：① 组件有没有漏掉信息架构已有的 ② 有没有发明信息架构没有的 ③ 每页三态齐不齐 ④ 跨页协议场景对不对。

**页面规格五要素**（每个页面必备）：

1. **布局分区**：用表格列出页面的分区（位置 / 说明）。复杂页面用「从上到下、从左到右」的顺序，必要时画 DOM 分区骨架。桌面端写视口与栏宽，移动端写 max-width 容器。
2. **组件清单**：每个分区下的组件给「组件名 / 状态变体 / 数据来源」三列。状态变体写清该组件有哪些视觉/交互形态（默认、加载中、选中、禁用等）；数据来源标注 API 或静态配置，让前端知道从哪取数。
3. **关键交互**：列出最重要的 3-6 个交互行为（点击后发生什么、状态如何切换、是否触发新请求/新对话）。
4. **状态处理**：用表格覆盖三种全局状态——加载态（骨架屏/占位）、空态（引导文案而非「暂无数据」）、错误态（错误描述 + 重试入口）。有演示模式的产品还要写 API 不可用时如何兜底。
5. **跨页面协议**（全局一节，不属单页）：定义页面间如何跳转与传参——
   - Agent 导航桥接：Agent 工具返回路由指令 → SSE 适配器发 `navigate`/`populate`/`action` 事件 → 前端写桥接存储 → 目标页加载时读取并自动配置状态（如打开某学生详情抽屉）。
   - 页面间数据传递表：场景 / 触发方 / 目标页 / 传递数据（如学情面板→学生管理传学生 ID）。

**组织建议**：同一端多页面用统一模板（如教师端 7 页、学生端 6 页、家长端 2 页），每页结构一致，便于评审与生成。

**示例——单页规格表（节选）**：

| 分区 | 位置 | 说明 |
|------|------|------|
| 侧边栏 | 左固定 232px | 品牌 + 新建对话 + 历史列表 + 导航图标 |
| 对话区 | 中央自适应 | AI 气泡（左对齐强调色）/ 用户气泡（右对齐白底） |
| 输入区 | 底部固定 | 多行输入 + 文件上传 + 发送 |

| 组件 | 状态变体 | 数据来源 |
|------|---------|---------|
| 对话气泡 | AI 气泡 / 用户气泡 | 流式对话 |
| 输入框 | 默认 / 输入中 / 发送中禁用 | 用户输入 |
| Agent 状态栏 | 分析中 / 执行中 / 等待审批 / 错误 | phase 事件 |

**示例——跨页面数据传递表**：

| 场景 | 触发方 | 目标页 | 传递数据 |
|------|--------|--------|---------|
| 学情面板→学生管理 | 点击关注学生卡 | 学生管理 | 学生 ID（自动开详情抽屉） |
| Agent→诊断面板 | Agent 返回诊断组件 | 障碍诊断 | 班级 ID + 考试 ID |

## 文档结构

1. 引言：引用设计系统，说明本份覆盖哪些端/页面
2. 按端分章（教师端 / 学生端 / 家长端）
3. 每页五要素：布局分区 → 组件清单 → 关键交互 → 状态处理
4. 跨页面交互协议（全局一节）：Agent 导航桥接 + 页面间数据传递表

## 及格线

- ☑ 每个页面五要素齐全（布局/组件/交互/状态/跨页）
- ☑ 组件清单含「状态变体 + 数据来源」两列
- ☑ 加载/空/错三态均有设计，空态有引导
- ☑ 有跨页面跳转与传参协议
- ☑ 视觉细节引用设计系统而非重复定义

## 最易挂的坑

- **只有布局没有状态**：只画了正常态，加载/空/错三态缺失，开发时各写各的，体验割裂。
- **组件清单无数据来源**：列了组件名却不标从哪个 API 取数，前端只能猜，原型与真实数据对不上。
- **跨页面协议漏写**：Agent 跳转、抽屉预开等跨页联动没有统一约定，前端用临时硬编码，后期难维护。
