# 39 Agent 输出界面前端 SSE 渲染策略写作框架

## 回答什么问题

产品含流式 AI 输出时，后端吐出的 SSE 事件流如何**在前端变成连贯、可交互的界面**？本文档是 Agent 事件协议（另一份文档定义）的「渲染层对应物」：定义前端如何消费事件、组装消息、管理渲染状态，并支撑内联面板、工具卡片、审批卡片等富交互。

## 怎么设计（框架/步骤）

**1. 三层渲染架构**

- **传输层（Transport）**：SSE / WebSocket / 本地直连三者可切换。通过适配器模式接入，视图层不感知传输协议。
- **状态层（ChatRuntime）**：接收统一 `ChatEvent`，维护对话状态（消息列表、当前阶段、活跃工具调用），向渲染器分发。核心接口含 `connect / subscribe / getState / sendMessage / cancel / retry / addToolResult`。
- **视图层（Renderers）**：事件路由器 + 各渲染器（phase / text / tool / component / navigate）。

**2. 消息组装器**：SSE 事件流拼接为结构化 `UIMessage`，由多个 `MessagePart`（text / tool_call / component）按时间顺序组成——这是「交错渲染」（文本与工具调用穿插）的基础。

**3. 事件 → 渲染映射**（核心，必须给全）：用表定义每种事件的生命周期与 UI 表现——

- `phase`：Agent 阶段切换（thinking/executing/awaiting_approval…）→ 作用于全局状态栏 + 思考气泡/审批卡片
- `text`：流式文本 → 追加到当前消息，维护**流式 Markdown 解析状态机**（code/math/table 未闭合时缓存，收到非 text 事件或超 5s 强制闭合），KaTeX 增量渲染
- `tool_call`/`tool_args`/`tool_result`：工具调用卡片的**状态机**（preparing → executing → completed/failed），含计时器、参数流式渲染、结果分发到富 HTML 渲染器
- `component`：对话流内嵌可交互面板（独立生命周期：骨架→取数→用户操作→可关闭）
- `navigate`/`populate`/`action`：写入桥接存储触发跨页跳转，目标页 `onload` 消费后立即清除防重复
- `done`：清计时器、强制闭合未完成的 Markdown 块、持久化对话、解发送锁

**4. 对话气泡渲染管线**：定义用户/AI/系统三类气泡的样式与对齐；思考气泡的三点跳动动画；内容块交错渲染顺序。

**5. 工具调用卡片**：四阶段生命周期表（准备/执行/完成/失败）含视觉与时长；审批卡片（黄色边框 + 确认/取消 → `addToolResult`）。

**6. 组件注册与扩展**：维护工具结果渲染器、内联面板渲染器、工具显示名三个注册表；新增类型只需「定义渲染函数 + 注册映射 + 注册名称图标」三步，不改核心代码。

**7. 性能策略**：帧同步文本渲染（requestAnimationFrame 批量消费）、虚拟滚动（超阈值启用）、图片渐进加载（IntersectionObserver 懒加载）、SSE 断连恢复（指数退避 + `Last-Event-ID` 续传）。

**示例——事件→渲染映射核心表**：

| 事件 | 生命周期 | UI 表现 |
|------|---------|---------|
| phase: thinking | 全局状态栏 | 底部思考气泡（三点跳动） |
| text | 追加到最后 TextPart | 流式 Markdown 状态机，未闭合则缓存 |
| tool_call | preparing→executing→completed | 卡片骨架→参数+计时器→✅/❌ |
| component | 插入可交互面板 | 骨架→取数→用户操作→可关闭 |
| navigate/populate | 写桥接存储 | 触发目标页加载，消费后清除 |

**示例——工具调用卡片四阶段**：

| 阶段 | 视觉 | 计时 |
|------|------|------|
| preparing | 灰色骨架 + 工具图标 | <1s |
| executing | 工具名 + 参数预览 + 脉冲边框 | 取决于耗时 |
| completed | ✅ + 耗时 + 可展开结果 | 持续 |
| failed | ❌ + 错误 + 重试按钮 | 持续至重试成功 |

**核心指标（写进设计目标）**：首 token→UI P95 < 3s；text 渲染 ≥30fps；200 条内无退化，超出启虚拟滚动；断连 3s 内自动重连。

## 文档结构

1. 系统定位与设计目标（指标：首 token→UI、帧率、断连恢复）
2. 三层渲染架构（传输/状态/视图）+ ChatRuntime 接口
3. 事件→渲染映射（逐事件类型生命周期与 UI）
4. 对话气泡渲染管线 + 工具调用卡片
5. 组件注册与扩展机制
6. 性能策略

## 及格线

- ☑ 有传输/状态/视图三层架构且传输可替换
- ☑ 逐 SSE 事件类型给生命周期与 UI 表现
- ☑ 工具调用卡片有完整状态机（含审批）
- ☑ 组件可扩展（注册表 + 三步扩展）
- ☑ 有断连恢复与性能策略（虚拟滚动/帧同步）

## 最易挂的坑

- **只写 text 事件**：漏写 tool_call/component/navigate 等事件的渲染契约，前端内联面板与跳转无据可依。
- **流式 Markdown 不处理未闭合**：代码块/表格只收到一半就直接渲染，界面出现半成品。
- **扩展写死核心**：新增一种工具结果渲染要改主循环代码，违反「注册即可用」原则。
