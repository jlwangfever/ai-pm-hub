# 40 检索增强知识系统（Agentic GraphRAG）写作框架

## 回答什么问题

当产品需要「基于知识库回答/出题/诊断/推荐路径」且纯向量检索不够用时，如何设计一套**既能语义匹配、又能关系推理**的知识系统？本文档回答：从向量检索的四类盲区出发，如何引入图结构做多跳推理、混合检索、子图注入与自校正，并定义图谱构建、工具设计与评估。

> 去行业化说明：下文用「学科知识图谱」「知识点节点」「前置依赖关系」「专业符号」等中性表述；具体学科（如化学）仅作举例，不写成方法论本身。

## 怎么设计（框架/步骤）

**1. 演进定位：Vector RAG → Graph RAG → Hybrid**

先写清当前向量检索的结构性盲区（无多跳推理 / 无因果溯源 / 无路径推荐 / 非结构化上下文），再定义图检索补什么、两者如何互补（向量做语义匹配，图做关系推理，不互相替代）。给设计目标量化表（多跳准确率、查询延迟 P95、路由分类准确率、路径合理率）。

**2. 混合检索策略（三路径）**

- **Vector 路径**（factual 单跳）：关键词+向量双路召回 → 提取知识点标签 → 补结构化元数据。
- **Graph 路径**（relational 多跳）：实体名三级匹配（精确 / 编辑距离≤2 / 语义向量兜底）→ 按关系类型展开子图（各关系给展开深度，如前置双向深 3、深化正向深 2、关联双向深 1）。
- **Hybrid 路径**（comprehensive）：Vector+Graph 并行 → **RRF 融合（k=60）** → LLM 重排序 → 注入 Prompt。

**3. 知识子图 → Prompt 上下文注入**

按关系类型**分层结构化注入**（四层，各自优先级与格式）：

| 层级 | 关系 | 优先级 | 注入格式 |
|------|------|:-----:|---------|
| L1 | 前置依赖 | 最高（必读） | 「学习 X 前需掌握：A(已掌握)/B(薄弱)」 |
| L2 | 深化扩展 | 高 | 「A 深化为 B，增加了…」 |
| L3 | 横向关联 | 中 | 「关联概念：C、D」 |
| L4 | 典型示例 | 低 | 「典型反应/例题：…」 |

并给：掌握度感知裁剪（已掌握一行带过、薄弱展开含示例）、Persona 感知注入（教师全结构/学生鼓励语气/家长通俗）、Token 预算（各场景上限，溢出按优先级裁剪）。

**4. 自校正检索循环（核心难点）**

把检索建模为 `Retrieve → Critic → Supplement → Retrieve` 闭环，对 Agent 透明（单次工具调用返回完整子图）。

- **Critic Node 三维评估**：拓扑完备性（前置链是否连通到基础层）、关系充足性（该查询类型必选/期望关系覆盖）、深度充足性（扩展深度是否满足认知层次需求）。三者各给判定逻辑与通过标准。
- **Supplement Retrieval 四策略**：按 `missing_type`（prerequisite / related / example / depth）执行对应补充检索的 Cypher 模板。
- **安全边界**（任一触发即停）：最大校正轮数（如 3）、最大总跳数（如 3）、Token 预算（子图 ≤ 上下文窗口 30%）。超限进 Fallback：强制合成 + 置信度降级标注 + 中文提示 + 异步补偿。
- **环路防护**：visited 全局集合、path_hash 去重、PREREQUISITE 环检测与解除。

**5. 知识图谱构建（本体 + 流水线）**

- 本体：节点类型（维度/主题/知识点/示例/真题引用）+ 关系类型（归属/前置/深化/关联/示例/考察/顺序）及属性约束、索引策略。
- 四阶段构建流水线：课标教材提取（认知动词→认知层次映射、粒度拆分归并）→ 关系标注（教材顺序/认知递进规则 + LLM 判断 + 专家抽检审核 + 环路检测）→ 真题关联（LLM 标注知识点 + 三级名称匹配 + 批量写入去重）→ 典型示例生成（质量校验）。
- 增量更新与考纲变更同步机制（软删除 + 重推断 + 环路复检）。

**6. Agent 工具设计**

定义图工具（探索/学习路径/前置检查）的输入规范、内部执行流程（实体提取→模糊匹配→子图展开→格式化→suggested_next 智能建议）、返回 Schema、Persona 过滤（对学生隐藏诊断元数据）、工具协作图（与搜索/出题/诊断工具的五步链）。

**7. 评估与验证**

六维：多跳推理准确率（测试集 + 评分 rubric + Baseline 对比）、学习路径质量（教师评分矩阵加权）、上下文注入质量（LLM-as-Judge 盲评）、检索延迟（P50/P95/P99 benchmark）、图质量指标（覆盖率/关系准确率/密度/无环性/孤立节点）、回归测试（Golden Case + CI 集成）+ 持续监控与三级降级策略。

## 文档结构

1. 系统定位（Vector 盲区 → Graph 变革 → 架构位置 → 设计目标）
2. Agent-Graph 交互架构（状态扩展 / Graph Researcher / Query Router 三类分类）
3. 混合检索策略（三路径 + 实体三级匹配）
4. 知识子图 → Prompt 分层注入
5. 自校正检索循环（Critic 三维 + 四补充策略 + 安全边界 + Fallback + 环路防护）
6. 知识图谱构建（本体 + 四阶段流水线 + 增量）
7. Agent 工具设计（含 Persona 过滤）
8. 评估与验证（六维 + 降级）

## 及格线

- ☑ 写清 Vector 四类盲区与 Graph 互补定位
- ☑ 混合检索给融合策略（RRF k 值 + 重排序）
- ☑ 自校正循环有三维评估 + 触发条件 + 安全边界（轮数/跳数/Token）
- ☑ 子图注入按关系分层且带 Token 预算
- ☑ 图谱构建有本体与流水线，工具设计含 Persona 过滤
- ☑ 有量化评估体系与降级策略

## 最易挂的坑

- **自校正无安全边界**：只写补充检索不写轮数/跳数/Taken 上限，易陷入无限循环或上下文爆炸。
- **混合检索只并列不融合**：Vector 与 Graph 结果简单拼接，缺 RRF/重排序融合，质量上不去。
- **图构建靠人工全标**：不设计自动推断规则 + LLM 判断 + 专家抽检的分层策略，图谱准确率与成本不可控。
