## 片段一：文件头——数据块的三条元规则

**示范点**：成品 DESIGN.md 的头部不只写标题，还要声明**合成来源、使用方式、冲突裁决规则**——这三条让 AI 在读到任何歧义时知道听谁的。

```markdown
> **合成来源**：[36-设计系统]（视觉语言）+ [40-前端页面设计规格]（15 个页面的布局/组件/状态/交互）
> **使用方式**：AI 生成或修改任何界面代码前，必须先读本文件。四段结构：
> ① 设计参数结构化数据块 → ② 跨页面可复用组件模式 → ③ 设计理念的可执行约束规则
> → ④ 整体约束与已知缺口。
> 参数冲突时以第一段数据块为准；数据块未覆盖的，查第四段缺口表，**禁止自行发明设计参数**。
```

## 片段二：第一段数据块——null 与缺口编号交叉引用

**示范点**：源文档没定义的参数写 `null` 不是终点，要**当场挂上缺口编号（gap: "G-XX"）**，让数据块和缺口表形成双向索引；同时每个色值带「声部」语义注释。

```yaml
color:
  primary:
    oxford_blue: "#002147"    # 【系统的声音】主按钮 / 侧边栏 / 标题强调
    teal: "#0d7377"           # 【AI 的声音】AI 对话气泡 / AI 按钮
    warm_paper: "#faf8f5"     # 【纸的声音】页面主背景 / 卡片底色
  semantic:                   # 状态色：仅「浅色背景 + 深色文字」标签式呈现
    pass:    { bg: null, text: null, intent: "极浅绿底 + 深绿字", gap: "G-03" }
    warning: { bg: null, text: null, intent: "极浅黄底 + 深棕字", gap: "G-03" }

typography:
  heading:
    family: null              # 仅描述为「衬线展示字体」，未指定具体字体 → G-05
    candidate_hint: "某衬线字体（上游另一文档已用于大号得分数字）"
```

## 片段三：第二段复用矩阵——页 × 模式的 ● 矩阵

**示范点**：抽象组件模式之前先画**复用矩阵**：行 = 组件模式（P-01…P-18），列 = 页面，格子 = 是否使用。它的价值：① 一眼看出哪些模式真的「跨页重复」（值得抽象）② 单页独有的样式不进模式库 ③ 资料没说清的格子标 `?` 并挂缺口编号，不猜。

```markdown
### 2.0 复用矩阵（●=该页使用）

| 模式 | T1 对话 | T2 工作台 | T3 学情 | … | S6 登录 | P2 家长面板 |
|------|--------|----------|--------|---|--------|------------|
| P-01 对话气泡   | ● | | | | | ● |
| P-05 底部 TabBar | | | | | ● | ? |   ← 资料未说明家长端是否有 TabBar → G-13
| P-14 页面三态   | ● | ● | ● | | ● | ● |  ← 全 15 页强制
| P-18 [某学科]式渲染 | ● | ● | | | | |

（P-05 在 P2 标 `?`：上游文档未说明 → 编入缺口表 G-13）
```

## 片段四：组件模式的「契约」写法

**示范点**：每个模式 = **用于**（哪些页）+ **契约**（结构与视觉规格）+ **状态**（变体），并且跨页有差异时**把差异写进同一条目**，不另开模式。

```markdown
### P-01 对话气泡（chat-bubble）
- **用于**：T1、S1、P2 浮动 AI 面板
- **契约**：
  - AI 气泡：主题色浅色底、左对齐、圆角
  - 用户气泡：白底 + 浅灰边框、右对齐
  - 气泡内容支持专业符号渲染（见 P-18）
- **状态**：流式输出中（SSE 逐字渲染）；一端额外有工具调用卡片（带实时计时器）
  与审批卡片（黄边框，确认/取消）

### P-14 页面三态（page-states）—— 全局强制模式
- **用于**：全部页面，任何数据驱动区块
- **契约**：加载态=骨架屏/数字闪烁；空态=图标+**引导性文案**（必须告知下一步动作，
  禁止孤立「暂无数据」）；错误态=错误描述+重试入口
- **降级**：某页有第四态「演示模式」——API 不可用时用静态示例 + 模拟数据标识
```

## 片段五：第三段约束规则——编号 + 严重级 + 可机械校验

**示范点**：约束规则不是散文，是**表格**：C 编号（可被代码评审引用）+ 🔴/🟡 严重级（🔴违反即返工）+ 出处（理念来自上游哪一节）+ **可机械校验标准**（能写成 lint 规则或检查项，不是「注意统一」这类模糊词）。

```markdown
| # | 规则 | 出处 | 可验证标准 |
|---|------|------|-----------|
| C-01 🔴 | **色彩声部不得串位**：蓝=系统 UI，青=AI，暖纸=背景 | 三主色「各司其职」 | 主按钮/导航/标题只用 `#002147`；AI 气泡/AI 按钮只用 `#0d7377`；禁止互换 |
| C-04 🟡 | **氛围透明度上限** | 视觉主题「被注意到即超标」 | 网格 `opacity ≤ 0.04`；水印 `opacity ≤ 0.03`、`rotate(-2deg)`；超出即违规 |
| C-08 🔴 | **状态三件套强制** | 设计系统 7.8 + 页面规格逐页状态 | 任何数据区块必须实现 loading/empty/error 三态；空态文案必须是引导动作句式 |
| C-13 🟡 | **反馈渠道分流** | Toast vs 弹窗的定位差异 | 轻反馈用 Toast（3s 自灭）；需确认的操作用弹窗；禁止用弹窗做成功提示 |
```

## 片段六：第四段缺口表——编号 + 影响 + 建议默认 + 回填机制

**示范点**：缺口表是 DESIGN.md 的**生命周期设计**：每条缺口给「建议默认」让 AI 不被阻塞；文件尾声明**回填机制**——缺口确认后回填第一段数据块并删除 G 编号，缺口表因此会越用越短。

```markdown
### 4.2 已知缺口（生成代码前需产品方确认，或按「建议默认」实现并标注 TODO）

| # | 缺口 | 影响 | 建议默认（待确认） |
|---|------|------|--------------------|
| G-03 | 语义色三态**无 hex** | 状态徽章无法精确实现 | 参考 Tailwind green-50/green-800、amber-50/amber-900、red-50/red-800 |
| G-05 | 标题字体**未指定具体字体** | 标题/品牌字体不定 | 沿用上游已用于大号数字的衬线字体 + 中文衬线回退 |
| G-13 | 某端**是否有底部 TabBar 未说明** | 导航结构 | 以顶部 Tab 为唯一导航，不加底部 TabBar |

> 缺口项确认后应回填至第一段数据块并删除对应 G 编号。
```

## 把样例换成新领域的动作清单

1. **换合成来源**：头部「合成来源」改为你项目里的设计系统 + 前端页面规格两份上游文档。
2. **换数据块**：色值/字体/组件 token 全部重提；本领域特有的渲染引擎（样例为专业符号渲染）替换为你的领域格式；`null + gap 编号` 机制原样保留。
3. **换页面索引与矩阵**：页面代号（T1/S1/P1…）按你的端与角色重编；复用矩阵重画，`?` 照用。
4. **换约束规则**：C 编号规则逐条从你的设计理念翻译；🔴/🟡 分级、出处、可机械校验标准三个列原样保留。
5. **换缺口表**：重盘上游未定义项；建议默认只给方向不给拍板；回填机制原样保留。
6. **不要照抄**：样例里的「声部」隐喻（系统/AI/纸）、实验室笔记本子主题、家长端低认知负荷原则等都是 [示例项目A] 专属设计决策，新领域应从自己的设计系统重新推导。
