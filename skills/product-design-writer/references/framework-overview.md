# 产品设计（第 4 阶段）框架总览

> 为产品设计阶段的 23 份设计文档补齐「分层组织 → 素材对应 → 按需加载 → 统一主线/及格线/红线」。
> 本文件是总览，每份文档的详细框架见同目录下 20-41 各文件。
>
> **跨领域说明**：本技能学的是「这类设计文档怎么写」的骨架。文中出现的「题库 / 真题 / 出题 / 批改 / 学情 / 家长端」等，都是样例（教育类产品）的实例化命名——换到新领域时，**分层、状态机、矩阵、降级链、及格线、红线全部不变，业务名词按新领域替换**（如「题库→内容库」「真题→历史资产」「批改→识别入库」「学情→使用分析」「家长端→外围干系人端」）。

## 一、设计是分层的（单向依赖原则）

产品设计文档按「从 0 到 1 的设计递进顺序」组织。每层设计建立在前面各层决策之上，**后面的文档可引用前面的决策，不能反过来**；每份文档只写该阶段能做的决策。

| 设计层 | 文档 | 核心内容（该层能做的决策） |
|--------|------|--------------------------|
| **第 1 层 结构** | 20 信息架构 | 三端页面树、导航机制、组件-数据源绑定、子角色菜单差异 |
| **第 2 层 流程与权限** | 21 页面流程 + 22 权限模型 | 用户如何操作（核心流程、跨端闭环、SSE 与审批中断）；谁能操作什么（角色表、资源-动作矩阵、审批状态机） |
| **第 3 层 业务系统** | 23-28 | 六大业务模块的独立设计，消费第 2 层产出的流程与权限约束 |
| **第 4 层 Agent** | 29 | AI 如何串联所有业务能力，工具集在此定义 |
| **第 5 层 数据与分析** | 30-31 | 消费业务与 Agent 产出，做学情分析与质量评测 |
| **第 6 层 支撑** | 32 | 基于前述所有系统，为外围角色提供数据视图与通知 |
| **第 7 层 技术基础** | 33-37 | 数据模型 → API → 设计系统 → 桌面/部署 → 技术选型 |
| **第 8 层 前端整合与原型验证** | 38 + 41 + 43 | 散落前端设计集中为完整页面规格；用原型验证设计可行性；把 35+38 压缩成 AI 自动遵守的 DESIGN.md |

> **依赖方向**：第 N 层可引用第 1…N-1 层的结论；第 1 层不依赖任何尚未编写的设计规范。业务系统（第 3 层）必须明确标注「本系统设计消费了哪些前置流程/权限约束」，而非重新定义。

## 四、统一写作主线

```
定输入（素材）→ 套分层框架 → 产核心表/状态机/矩阵 → 写"不在范围内" → 过及格线
```

每份设计文档都必须：落在正确设计层 → 有结构化产出（页面树/流程/状态机/矩阵/管线）→ 明确边界（不在范围内）→ 过该文档及格线自检。

## 五、及格线总表（全阶段通用要求）

| 文档类型 | 通用及格线（每项都须满足） |
|----------|--------------------------|
| 结构层（20） | 三端页面树完整；导航机制明确（SPA/MPA 决策）；组件-数据源 1:1 绑定；子角色菜单差异有矩阵 |
| 流程与权限（21-22） | 核心流程有流程图+关键接口；跨端闭环有写操作节点；权限先定角色表再定资源-动作矩阵；审批有状态机+边界 |
| 业务系统（23-28） | 有端到端管线/状态机；有明确降级链或失败态；数据结构落到字段；接口给协议与错误码；写"不在范围内" |
| Agent（29） | 工具集目录清晰；Persona 与权限边界明确；审批门控（GuardState）定义清楚 |
| 数据与分析（30-31） | 分析维度有定义；预警/评测有指标与阈值；评测有确定性测试集与 CI 门禁 |
| 支撑（32） | 外围角色数据权限最小可见；通知渠道与触发条件明确 |
| 技术基础（33-37） | 实体字段规格；API 端点矩阵+错误码；选型有决策理由 |
| 前端/验证（38-41, 43） | 页面集中规格；SSE 协议定义；原型可对照验证清单；DESIGN.md 零发明、token 带规则、缺口表完整 |

## 六、统一红线（所有文档通用）

1. **状态机必须有边界与异常分支**：每个状态机给出状态枚举、转移条件、超时与失败态（如 `ERROR`/`DISCARDED`），禁止只画happy path。
2. **算法必须可复现**：确定性校验（如数值/逻辑一致性）用确定性算法实现并设 100% 安全红线，不依赖同一模型自检；规则库做软告警。
3. **数据结构必须落到字段**：实体/请求/响应写清字段名、类型、必填、含义，禁止只给概念。
4. **接口必须给协议与错误码**：关键操作标注 HTTP 方法、路径、参数、成功/失败响应与错误码（如 400/401/403/404）。
5. **每个系统必须写"不在范围内"**：明确声明本系统不做什么，防止需求蔓延与跨层越权。
6. **分层单向依赖**：后层引用前层决策，禁止在前层文档中预设后层才能确定的细节。
