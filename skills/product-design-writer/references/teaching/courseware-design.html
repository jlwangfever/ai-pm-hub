再学 · AI 出题（解剖样板）

一条环节可替换的流水线

怎么设计 ①：给 AI 下命令（Prompt 三层）

像给新老师写教案：① 角色设定（资深化学老师）+ 每类题型硬约束（选择必 4 选项+埋陷阱）② 格式规范（镣铐）：化学式必须规范书写——LLM 天然不守格式，源头统一，下游渲染才不乱。在源头戴镣铐，镣铐内自由发挥 ③ 用户指令：有真题→模仿变体；无→从零创作

为什么：管线要"环节可替换"？

换模型？只动第 1 步。加审核规则？只动第 3 步。换检索？只动第 0 步。结构不变，环节可换——改一个环节不碰整条线，这是工程设计的通用骨架。

Agent 的出题工具 = 同一条管线，只是入口从"点按钮"变"说句话"。

再学 · AI 出题的 RAG 设计

AI 出题凭什么像高考题？——RAG 三步走

① 为什么按知识点切片？

一题几个知识点 = 几个向量；embedding 文本拼入考点+题型+难度+来源+题目(截 500 字)+答案——语义完全由"考什么"承载。

② 为什么两层检索？

第一层简单匹配初筛 top20（知识点重叠打分、难度匹配优先）；第二层向量精筛 top5（相似度排序）——向量调用花钱花时间，先花小钱，再花大钱。

③ 为什么不足 3 道不用 RAG？

相似真题 <3 道 → 纯 LLM 生成（参考太少反而带偏风格，宁缺毋滥）；≥3 道 → "基于以下真题生成变种题" + 最多 5 道题干+答案。

三个工程决策：切片让"考点"成为检索主信号 · 两层检索先便宜后精细 · RAG 不足宁可不给，不硬凑参考。

再学 · 业务系统怎么设计 ②

产品设计文档的标准格式——一个模板套所有模块

通用模板（每份文档都套这个）

一、系统定位与设计目标

· 在架构中的位置（跟上下游什么关系）
· 设计目标（要达成什么）
· 核心指标（怎么衡量做得好不好）
· 不在范围内的功能（明确边界）

二、核心设计内容

· 用户场景（谁、在什么情况下用）
· 业务流程（一步一步怎么走）
· 关键设计决策（为什么这样而不是那样）

三、与上下游模块的衔接

· 输入依赖什么 · 输出触发什么 · 设计约束来自哪里

实例对照 · OCR 批改（真实文档原句）

▸ 对应「在架构中的位置」
"OCR 批改系统是 ChemAI 教学工具链的入口环节——位于教学价值链最上游"

▸ 对应「设计目标 + 指标」
"批改效率 6h→45min / OCR 准确率 >95% / 端到端 <5min"

▸ 对应「不在范围内」
"不处理手写公式识别、不做实时视频流、不做跨校对比"

▸ 对应「业务流程」
"10 步批改管线：上传→OCR→学生提取→答案匹配→批改→确认→入库→诊断→统计→报告"

▸ 对应「关键设计决策」
"为什么三引擎识别？为什么教师确认在入库前？为什么失败用多模态兜底？"

▸ 对应「与下游衔接」
"批改入库后自动触发障碍诊断 → 班级统计 → 报告生成"

为什么要统一模板？——强制每份文档想清楚"边界"和"关键决策"，格式一致才能模块间对比、评审。这个模板不挑产品——用户成长体系、订单调度引擎、内容推荐策略……全部套这个格式。写不出"边界"和"关键决策"的模块，就是没想清楚的模块。

三条原则（带反例）

1. 单向依赖

后面的引用前面的，前面绝不依赖后面。
反例：信息架构里写"详见 Agent 设计"——Agent 还没写。

2. 每层只做该层的决策

架构层不定义业务流程，业务层不选技术栈。
反例：在 OCR 模块里决定用 PostgreSQL——那是技术落地的决策。

3. 设计约束向下传递

权限定义 → 业务消费 → Agent 遵守。
反例：先设计 Agent 再补业务——工具全是对空气的调用。

动手顺序永远一样：先画页面树 → 再画流程 → 再拆业务模块 → 最后才考虑技术实现。

怎么设计：三个问题

① 什么时候需要入口分类器？——产品里有"纯页面跳转"和"要干活"两种请求，且跳转不该花 LLM 成本时。

六个核心概念

StateGraph图的蓝图：定义 State 结构 → 注册节点 → 连边 → compile

再学 ④ · 护栏怎么设计

护栏怎么设计？——每闸回答一个问题，审批讲哲学

❓ 为什么这么设计

四闸 = 四个设计问题

• 第 1 闸：这个工具缺什么参数会出事？→ 列出必填项（如搜题 keyword > 2 字）
• 第 2 闸：调用多少次会失控？→ 按破坏性分级限次（破坏性 1 次 / 辅导类 5 次）
• 第 3 闸：什么情况算"重复"？→ "工具名 + 参数"相同即重复
• 第 4 闸：哪些操作必须人点头？→ 维护一张破坏性操作清单（布置练习、删除题库）

审批的哲学：不是禁止，是暂停等确认

完全禁止 = 功能废了（老师再也布置不了练习）
暂停等确认 = 功能能做，但必须人点头

流程：Agent 暂停 → 前端弹确认卡片 → 老师点确认 → 从断点恢复执行。

安全不是功能的对立面——它们是同一个设计的两面。

模板：给每个工具回答四个问题——缺什么会出事 / 多少次会失控 / 什么算重复 / 要不要人点头。四个答案 = 你的护栏设计。

工具怎么设计？——拆动作 → 写规格 → 定规矩

❓ 为什么这么设计

1

拆动作：需求 → 动词 → 工具

把产品功能拆成"Agent 必须会做的动作"，每个动词一个工具。老师要"搜真题、出题、存题库、诊断班级、布置练习"→ 出题 9 个工具；"读文件、改文件、执行命令"→ 文件 6 个工具。合并重复、砍掉伪需求。

2

写规格：四句话一份规格书（含 NOT for）

何时用 / 会发生什么 / 下一步 / NOT for。LLM 靠这些描述选工具——写不满 NOT for 的工具，就是会被误用的工具。

定规矩 · 案例：搜题三级搜索

本地关键词最快最便宜 → 不够再向量召回 → 还不够才联网。先花小钱，再花大钱。 限次 3 次/轮防死循环。

定规矩 · 案例：化学式标准化

LLM 天然不守格式。源头做归一化：50+ 化学式白名单自动包装。源头多花几毫秒，下游渲染 100% 正确。

四条铁律：① 边界清晰（NOT for 必写）② 按领域分组（分组是选工具的第一层索引）③ 限购次数（破坏性操作限最严）④ 结果分离（业务结果给 AI，界面指令给前端）。

数据与分析：效果怎么衡量？

这一层有两块：学情分析（数据给老师看）+ 评测体系（标准给 AI 定）——

学情分析

三维分析立方体：知识点 × 学生 × 时间——两两交叉各回答一个问题：

· 知识点×学生：这个知识点谁最薄弱？
· 学生×时间：这孩子进步了吗？
· 时间×知识点：教学干预有效吗？

三级主动预警：提示 警告 紧急
未登录 / 成绩下滑 / 错题率过高 → 自动告警（<5 分钟），并同步家长端

为什么三维交叉？——单一维度看不出问题：只看"错误率"不知道谁错、为什么错、有没有好转；三个切面组合才构成完整学情。

评测体系（预告）

学情分析回答"学生怎么样"，评测体系回答"AI 靠不靠谱"——Agent 会变（换模型/改提示词/加工具），变好变坏不能靠感觉。

为什么必须评测？——没有度量就无法迭代：发布门禁回答"能不能发"、趋势回答"变好还是变差"、评估先行回答"下一步开发什么"。

这一层的意义：学情分析（给人看）+ 评测体系（给 AI 定标准）——数据与分析回答"效果怎么样"，没有度量就无法迭代。

评测体系有什么？——七层，每层回答一个问题

把评测想成给 Agent 做"七项体检"，每项体检回答一个问题：

层体检什么回答的问题用什么查什么时候查
L0工具自身正确性每个工具干得对不对？确定性断言（纯逻辑，零 AI）每次提交
L1行为轨迹该用哪个工具、参数对不对、顺序对不对？黄金场景断言每次提交

• 夜间/发布前跑，分钟级，花 token
• AI 判官打分 + 攻击样本 + 端到端剧本
• 严重错误一票否决（化学错误/安全问题/端到端失败 → 拦发布）
• 分数只做趋势，不拦发布——AI 打分有噪声

为什么分快慢双层？——按成本定节奏：秒级免费的每天跑（拦坏 PR），分钟级花钱的发布前跑。② 慢跑层不用分数线门禁——AI 打分有固有噪声，用分数拦发布会误伤；真正拦发布的是"严重错误"。报告按层分组、按时间归档成趋势，回答"Agent 变好还是变差"。

再学 · 门禁与工作流怎么设计

门禁怎么设计？——两级门禁 + 先写评估再写代码

门禁两级

• 快跑层：100% 必须绿，任一确定性失败阻止合并
• 慢跑层：严重错误一票否决（化学错误/安全问题/端到端失败）
• expected_fail：红评估带标记 = 豁免（pending），不挡门禁；意外变绿 → 提醒移除标记
• 覆盖诚实：没测到的报"未触达"，0/0 不是 100%

工作流怎么设计：评估先行（eval-first）

评估即 spec：先写评估定义"什么算好"（此时全红）→ 开发到绿 → 移除标记转常驻。

红→绿的过程 = 开发进度。案例：文件四件套（read/write/edit/bash 沙箱）先写 L0 红评估（编码/路径穿越/敏感文件/注入）再开发；出题智能化先写交互场景（"我要出题"必须追问+按薄弱点推荐）再增强 prompt。

为什么两级门禁？——快跑层确定性失败"挂了就是真挂了"必须拦；慢跑层 AI 打分有噪声，用分数拦发布会误伤，只有严重错误一票否决。金句：能断言的用代码，不能断言的用 AI 评；先写红评估再开发——功能做完之前，"什么算好"就已经钉死了。
