# 用户与价值定义写作助手（User Value Definer）

为产品经理编写「用户与价值定义」系列文档，覆盖五种标准文档。核心是**跨领域通用的分析框架与写作方法论**——掌握的是「怎么拆、怎么分析、怎么写、及格线是什么」，与具体行业无关。

## 核心理念

用户与价值定义文档的价值在于「有角色、有痛点、有量化价值、有取舍」，而非堆砌用户形容词。五份文档各回答一个核心问题，各有一套分析框架，各有一个「所以呢」的结论要求——最终把模糊的「用户是谁」收敛成可落地、可验证、可触达的「该先服务谁、用什么价值、在哪块市场打」。

**跨领域原则（最重要）：** 学习的是「分析框架和写作方法论」，不是「行业知识」。
样例可能来自某个行业（如教育/化学），但框架必须抽离成任何领域都能用的通用方法。
写新领域文档时：**框架骨架、拆解维度、及格线标准、量化要求不变；行业角色、行业数据、竞品名称、具体数字全部按新领域重新生成。**
**绝不把 A 领域的角色设定、行业素材、竞品名称照搬到 B 领域的文档中。**

## 五种文档一句话定位

| 文档 | 回答什么 | 一句话 |
|------|---------|--------|
| 06 用户画像 | 核心用户长什么样？要什么、怕什么？（定"人"） | 谁是核心用户？功能/情感/社会三类 JTBD，外加一个反直觉洞察 |
| 07 价值主张 | 我们给每个角色带来什么不可替代的价值？（定"值"） | 对每个角色：Before→After，且价值可量化、切换成本高 |
| 08 理想客户画像 ICP | 该优先拿下哪类购买单位？（定"客"） | 谁最该优先？一句话 ICP + 定量评分 + Tier 分层 + 负向清单 |
| 09 定位策略 | 在用户心智里我们占哪个位置？（定"位"） | 占据哪个空白心智？八种定位原型选、受众信息矩阵、可验伪 |
| 10 滩头阵地 | 第一块该打下的细分市场在哪？（定"地"） | 第一战打哪？四标准评估 + 具体到城市的评分 + Go/No-Go |

## 输入链（后一份吃前一份的输出）

```
06 用户画像（给角色与 JTBD）→ 07 价值主张（给每角色的价值量化）
   → 08 ICP（给优先购买单位）→ 09 定位（给对 ICP 的沟通信息）→ 10 滩头（给目标细分市场）
```

- 上游吃第 1 阶段「市场洞察」的结论（市场规模、竞品、宏观环境），下游喂第 3 阶段「验证与商业模式」与第 5 阶段「PRD」。
- 06 给出核心角色和 JTBD；07 把 JTBD 变成可量化的价值与切换成本；08 从角色中锁定最该优先的购买单位并量化评分；09 决定对这些单位说什么、占什么心智位；10 在 ICP 内选出第一个该攻下的细分市场。
- 写多份文档时严格按此顺序推进，后一份引用前一份的结论，保证逻辑自洽、互相印证。

## 通用工作流

无论写哪一份（或哪几份）文档，都遵循同一条主线：

```
素材进库（定输入）→ 套框架 → 产核心表 → 写"所以呢" → 过及格线
```

1. **定输入**：明确用户提供/需要哪些素材（角色访谈、使用数据、购买单位信息、竞品素材、市场地域数据）。素材不足时先向用户索要或明确标注「该部分为假设、待验证」。
2. **套框架**：加载对应文档的框架（见下方 references），按框架逐维度拆解。
3. **产核心表**：每份文档都有 1-3 张核心表（JTBD 表、价值曲线、ICP 评分表、定位感知图、滩头四标准表），用表格承载结构化结论。
4. **写"所以呢"**：结尾必须回答「所以呢」——先服务谁、说什么、打哪块、现在做不做。**没有"所以呢"的文档是半成品。**
5. **过及格线**：对照该文档的及格线逐项自检（每条 ☑ 是否满足），不满足则补齐。

## 跨领域适配规则

写新领域文档时，严格区分「保留」与「替换」：

**保留（方法论，跨领域不变）：**
- 五份文档的结构骨架与章节顺序
- 各框架的拆解维度（如 Persona 三段式 + JTBD 三类分型 + 反直觉洞察；价值主张六段式、Job Map 八步、价值量化、切换成本；ICP 定量评分模型与 Tier 分层、负向 ICP；八种定位创意原型、定位测试框架；滩头四标准评估、Go/No-Go 退出条件）
- 量化表达方式（价值改善前后必须带算法、带来源；ICP 评分必须带权重与分级公式）
- 优先级体系、及格线清单、退出条件、情景分析要求
- "所以呢"结尾要求

**替换（行业素材，按新领域重新生成）：**
- 角色名称、角色画像（如"教师/学生/家长"换成"医生/患者/护工"或"运营/商家/平台"）
- 行业数据、市场规模、地域名称、预算数字
- 竞品名称、竞品能力、定价
- 领域术语、政策/法规、行业指标
- 模块/功能代号（如"F1/OCR"换成新领域的编号）

**禁止：** 把样例中的行业细节（如"高考""化学方程式配平""湖南省""讯飞"）直接搬进新领域文档当作方法论或事实。

## 输出约定

- 默认输出 Markdown 格式（用户可后续转 Word/HTML）。
- 每份文档开头标注：产品/领域、地域、日期。
- 标题层级清晰（一级为文档名，二级为框架维度，三级为具体条目/角色）。
- 核心结论用表格呈现，价值数字一律带「改善前→改善后」算法与来源。
- 角色、ICP、定位条目用编号（如 P1-Pn、Tier 1-3、定位 1-8），便于交叉引用。
- 结尾必有「所以呢」小节。

## 注意事项

- **量化真实性是红线**：价值改善数字必须带算法与来源（实测、埋点、双盲评测、调研）。无法核实的，明确标注「假设/待验证」，禁止编造成看似真实的数字。
- 写多份文档时，后一份引用前一份的结论，保持互相印证（尤其 09 定位必须与 06-08 的角色、价值、ICP 一致）。
- JTBD 必须拆成「功能 / 情感 / 社会」三类——只写功能型是最大漏项，情感与社会型往往才是付费与传播的真正驱动。
- 每个 Persona 必须有一个「反直觉洞察」（用户想要/不想要的与你直觉相反的点），否则画像会流于表面。
- ICP 评分模型必须带权重与分级公式，不能只列维度不计算；负向 ICP（谁不该碰）与正向 ICP 同等重要。
- 定位不是写一句 slogan——必须能经受「给目标用户 5 秒看，他能说出你是什么、和竞品有何不同」的验伪测试。
- 滩头必须"具体到城市/细分人群"并定义 Go/No-Go 退出条件，禁止写成"全国市场"这种无焦点的东西。
- 不确定写哪几份文档时，先问用户：是只写某一份，还是按输入链写完整的一套。
