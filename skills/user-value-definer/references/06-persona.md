# 06 用户画像（Persona）分析框架

## 回答什么问题

核心用户长什么样？他们要什么、怕什么、在什么场景下用产品？——为整个产品定"人"。
核心产出：识别 2-4 个核心角色（含 1 个次要角色），并产出每个角色的 JTBD、痛点和反直觉洞察，作为下游价值主张与 ICP 的输入。

## 怎么分析

### 1. 角色筛选
- 列出该领域所有可能的相关角色（使用方、购买方、影响方、被影响方），按「影响力 × 使用频率」选出 2-4 个核心角色。
- 每个角色给一个"人名化名 + 一句话人设标签"（如"张老师——想把时间还给教研"），便于全文档引用。

### 2. 每个核心角色写「基本信息」
- 姓名/年龄/角色/身份特征/规模（带多少下属或多少用户）/技术水平/使用约束。用 5-8 条要点承载。

### 3. JTBD 三类分型（必须齐全）
- **功能型**：当某情境发生时，具体要完成什么任务（动作 + 对象 + 标准）。
- **情感型**：使用产品希望获得或回避的"内心感受"（如不被替代感、专业成就感）。
- **社会型**：在同伴/上级/同行面前希望呈现的"社会形象"。
- 写法：`当……时，我要……，以便……`。每条 JTBD 带成功标准（可衡量）。

### 4. 三大痛点（带影响程度）
- 用表格列出 3 条痛点：痛点描述 + 影响程度（高/中/低，可标红黄绿）+ 量化证据（耗时/频率/成本）。
- 痛点须与 JTBD 对应——每条 JTBD 背后是未被满足的痛点。

### 5. 三大期望收益（带衡量标准）
- 表格列出 3 条收益：收益描述 + 可量化衡量标准（如"从 X 降到 Y""完成率 ≥ Z%"）。

### 6. 一个反直觉洞察（必写）
- 用户想要/不想要的，与你（和大众）直觉相反的一点。例："用户不想要完全自动化，要的是带优先级的建议，保留自己的决策权"。
- 必须写明「对产品的影响」（某功能应是建议而非指令）。这是画像从"罗列"上升到"指导设计"的关键。

### 7. 产品适配评估
- 用"功能/模块匹配矩阵"：左侧列产品核心能力，右侧标"直接命中 / 核心需求 / 谨慎使用 / 非目标"，并写说明。把画像结论落到具体功能取舍。

### 8. 行为深度佐证（提升深度，建议做）
- **一日时间线 / 一周节奏**：时间 × 活动 × 情绪 × 工具渠道 × 产品介入点。
- **动机地图**：内在动机 × 强度 × 产品满足方式。
- **功能交互频率与序列**：高/中/低频率分级 + 典型使用序列。
- **Onboarding 旅程**：触发→注册→首次使用→首次价值感知（Aha Moment）→持续使用→深度/传播，标情绪曲线与流失风险，圈出最高流失节点。

## 怎么写（结构）

1. **角色标题 + 人设标签**
2. **基本信息**（5-8 条要点）
3. **核心 JTBD**（功能/情感/社会 三型，每条带成功标准）
4. **三大痛点**（表：描述 + 影响程度）
5. **三大期望收益**（表：描述 + 衡量标准）
6. **一个反直觉洞察**（引用块 + 对产品的影响）
7. **产品适配评估**（功能匹配矩阵）
8. **行为深度分析**（时间线 / 动机地图 / 交互频率 / Onboarding，按角色选做）
9. **次要角色**简要说明（关注点与关键诉求）
10. **「所以呢」**：哪 1-2 个角色是产品必须死磕的、哪个反直觉洞察会改变设计

## 及格线

- ☑ 每个核心角色含基本信息 + 三类 JTBD + 三大痛点 + 三大期望收益 + 1 个反直觉洞察 + 产品适配评估
- ☑ JTBD 三类（功能/情感/社会）齐全，且每条带成功标准
- ☑ 至少有一个"反直觉洞察"并写明对产品的影响
- ☑ 痛点/收益带量化证据（耗时/频率/成本/比例），非纯形容词
- ☑ 结尾有「所以呢」（哪些角色优先、什么洞察改变设计）

## 最易挂的坑

- **只写功能型 JTBD**：漏掉情感/社会型，导致看不懂用户为什么付费、为什么传播。
- **反直觉洞察缺位或写成废话**："用户想要好产品"不是洞察；洞察必须违反直觉且可指导设计。
- **画像与产品脱节**：写了角色却没做"产品适配评估"，画像无法向下游（价值主张/PRD）传递。
