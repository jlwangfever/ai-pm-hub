# 07 价值主张分析框架

## 回答什么问题

我们给每个核心角色带来什么不可替代的价值？为什么他们该用我们而不是替代方案？——为产品定"值"。
核心产出：每个角色的 Before→After 价值跃迁、与竞品的差异化曲线、可量化的价值证据、以及"用了就回不去"的切换成本。

## 怎么分析

> **衔接上游（必做）**：价值主张必须直接引用 06 用户画像里的角色与 JTBD，不能凭空造"目标用户"。每个角色的价值主张 = 把该角色的 JTBD 变成可量化改善；写完后回流给 08 ICP 作为"优先服务该角色"的价值证据。

### 1. 分角色六段式（每个核心角色一套）
- **Who**：目标用户画像（引用 06 的角色，含规模、技术、决策权）。
- **Why（JTBD）**：引用 06 的三类 JTBD，作为价值主张的"靶心"。
- **What Before**：用户当前如何完成该任务——步骤序列 + 摩擦与痛点（量化耗时/成本/错误率）。
- **How**：产品用哪些能力解决（能力 × 解决的具体问题，对应关系表）。
- **What After**：改善后的状态，逐条对应 Before 的痛点。
- **Alternatives**：替代方案表——方案名 + 为什么不用（劣势/成本/盲区）。务必含"现状/行为惯性"这一隐形最强替代（如手工、Excel、不做的惰性）。

### 2. 汇总一句话价值主张
- 每个角色一句：「[产品] 是……——[核心收益]。」用表汇总。

### 3. 蓝海价值曲线（差异化可视化）
- 选 8-12 个关键竞争因素，定义清楚每个因素含义。
- 给本产品与各主要竞争类别在 1-10 分打分，构成对比表。
- 分析：在哪些因素上"减少/消除"（刻意不做）、在哪些上"创造/提升"（超越行业），形成"少数因素凸起 + 其他因素持平或以下"的蓝海配置。
- 指出竞品的结构性短板（如"通用平台不可能为单点做深度"）。

### 4. JTBD Job Map 深度拆解（八步）
- 把每个角色的 JTBD 拆成 8 个执行步骤：定义→定位→准备→确认→执行→监控→修改→结束。
- 每步四列：用户目标 / 当前痛点 / 产品方案 / 对应模块（或功能）。
- 附「耗时对比表」：手动 vs 产品，逐步节省 % + 总计节省 %（带算法）。

### 5. 价值量化（改善前后可测量对比）
- 对每个角色选 4-8 个指标，表列：指标 / 改善前 / 改善后（目标）/ 变化幅度 / 数据来源。
- 变化幅度必须算出来（如"-85%""+167%"），数据来源标实测/埋点/双盲/调研/访谈。
- 这是价值主张最硬的证据——没有量化就没有说服力。

### 6. 切换成本分析（为什么"回不去"）
- 对每个角色分析切换成本类型：流程/数据/时间/社交/心理/情感/安全等，逐类标强度（高/中/低）。
- 综合判断：深度使用多久后几乎无法回退。切换成本 = 护城河。

## 怎么写（结构）

1. **分角色六段式**（Who-Why-B-A-H-A-Alternatives，逐角色）
2. **一句话价值主张汇总表**
3. **蓝海价值曲线**（因素定义 + 对比表 + 减少/创造分析）
4. **Job Map 八步拆解**（逐角色，含耗时对比）
5. **价值量化表**（改善前→后 + 变化幅度 + 来源）
6. **切换成本分析**（逐角色，类型 × 强度）
7. **「所以呢」**：最不可替代的价值点是什么、差异化曲线凸起在哪、护城河多深

## 及格线

- ☑ 每个角色走完六段式（含 Alternatives，且含"现状/行为惯性"替代）
- ☑ 有蓝海价值曲线/竞品对比表，并指出"减少"与"创造"的因素
- ☑ 有 Job Map 八步拆解（至少核心角色）
- ☑ 价值量化表：每个数字带改善前→后算法与来源
- ☑ 有切换成本分析（类型 × 强度），说明护城河
- ☑ 结尾有「所以呢」

## 最易挂的坑

- **价值不量化**：只写"大幅提升效率"，无 Before→After 数字与来源，等于没证明价值。
- **漏掉"现状/行为惯性"替代**：最强竞品往往是"用户现在凑合用的老办法"，不是某个品牌。
- **曲线不分析取舍**：只打分不说明"为什么减少某些因素、创造哪些"，蓝海策略就立不住。
