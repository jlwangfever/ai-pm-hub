> 源文档：14-机会解决方案树.md

## 回答什么问题

把"期望成果"（通常就是 13 的 NSM 目标）拆成一棵**机会树**，再为每个机会长出若干方案与可证伪的实验，让团队知道"先解决哪个机会、用哪个方案、怎么验"。OST 是验证支线承上（吃 11 假设、13 NSM）启下（喂 18 优先级）的核心工具。

## 怎么分析

### 1. 期望成果（Desired Outcome）

- 一棵 OST 只服务**一个**期望成果（通常对齐 NSM，如"月诊断/处理量从 X 增到 Y"）。
- 给出量化分层：阶段 × 目标值 × 覆盖客户数 × 时间窗口。

### 2. 机会树（Torres 方法）

- 从期望成果向下拆出 8-12 个**机会（Opportunity）**，每个机会是"用户/业务尚未被满足的点"。
- 对每个机会计算 **机会评分**：`Importance × (1 - Satisfaction)`（重要性×不满程度，各 1-10 分）。分数越高越值得优先。
- 每个机会下挂 2-4 个**方案（Solution）**，标注已实施/设计中/未实施 + 优先级（P0/P1/P2）。

### 3. 机会优先级与证据深描

- 排序表：机会 × Importance × Satisfaction × Score × 状态 × 关联模块。
- 每个高分机会写**证据深描**：来自用户访谈/假设验证/干系人地图的具体证据；反直觉发现；方案战略价值。证据不足的机会要标"假设待验"。

### 4. 实验设计八要素模板

每个方案对应一个实验，固化八要素（可直接套用）：

| 要素 | 说明 |
|------|------|
| 实验名称 | 一句话可引用 |
| 所属机会 | 对应 OST 机会编号 |
| 待验证假设 | "我们相信[用户]在[场景]会[行为]，因为[理由]" |
| 实验方法 | 定性（访谈/可用性）/定量（A/B/埋点/计时） |
| 样本量 | 定性 5-8 人；定量按效应量计算 |
| 成功标准 | 量化通过/不通过阈值 |
| 实验周期 | 日历天数 |
| 失败预案 | 失败下一步 |
| 当前状态 | 未启动/进行中/已完成/搁置 |

### 5. 已"杀死"的方案墓地（Killed Solutions Graveyard）

记录被否决的方案：方案描述 → 被杀死的原因 → 杀死日期 → 替代方案。作用：避免 6 个月后团队重新讨论已被否决的方向。注明是永久 Kill 还是延迟（给复活条件）。

### 6. 解决方案比较矩阵 + 发现节奏 + OST 与产品模块映射

- 对关键机会的多个方案做比较矩阵（开发成本/覆盖/体验/风险/优先级）。
- 发现节奏（Discovery Cadence）：周/双周/月/季的固定发现活动 + 学习回顾模板。
- OST 与产品模块映射表：机会 → 模块 → 实施状态 → 评测关联。

## 怎么写（结构）

1. **摘要**：期望成果一句话 + 最关键的机会。
2. **期望成果量化分层**。
3. **机会树全貌**（机会×评分×方案，树状/列表）。
4. **机会优先级排序 + 证据深描**（Top 机会详写）。
5. **实验设计模板 + 关键实验详细设计**（八要素）。
6. **已杀死方案墓地**。
7. **解决方案比较矩阵**。
8. **发现节奏 + 学习回顾模板**。
9. **OST 与产品模块映射**。
10. **关键发现与战略建议**。
11. **「所以呢」**：先打哪个机会、哪两个方案是关键补缺、80% 精力放哪。

## 及格线

- ☑ 一棵 OST 只服务一个期望成果，且对齐 NSM。
- ☑ 机会用 `Importance×(1-Satisfaction)` 评分并排序，非凭感觉。
- ☑ 每个方案有实验八要素（含成功标准与失败预案）。
- ☑ 有"已杀死方案"墓地，写明原因与替代方案。
- ☑ OST 与产品模块有映射，且高分机会有证据深描（非空泛）。
- ☑ 结尾有「所以呢」（资源集中方向）。

## 最易挂的坑

- **机会不加评分就排优先级**：列一堆机会凭直觉排，无法向团队证明"为什么先这个"。
- **只有方案没有实验**：方案写得热闹，但没八要素（尤其成功标准与失败预案），无法证伪、无法执行。
- **缺"杀死方案墓地"**：被否决的方向反复被重提，浪费决策精力；也不利于新人理解战略取舍。
