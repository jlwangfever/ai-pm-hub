# 验证与商业模式分析框架总览

> 为八份验证与商业模式文档补齐「数据从哪来 → 怎么分析 → 怎么写 + 及格线」。
> 本文件是总览，每份文档的详细框架见同目录下 11-18 各文件。

## 一、素材 → 文档对应（写哪份，喂哪类素材）

| 素材类型 | 喂给哪份文档 |
|---------|------------|
| 用户访谈/田野观察/使用日志 | 11 假设识别与验证（用户行为假设）、15 干系人地图（角色诉求）、14 OST（机会证据） |
| 问题场景/痛点清单/现有替代方案 | 12 精益画布（问题与替代）、14 OST（机会来源） |
| 收入结构/成本结构/定价/财务数据 | 12 精益画布（收入与成本）、17 GTM（定价与单位经济）、18（ROI 与排期） |
| 指标数据/埋点/行为漏斗 | 13 北极星指标（NSM + 输入指标 + 反指标） |
| 竞品/渠道/市场分层信息 | 17 GTM（Battlecards/渠道 ROI/市场选择） |
| 组织关系/决策流程/风险事件记录 | 15 干系人地图（权力矩阵/决策链/风险登记册）、16 Pre-Mortem |
| 功能清单/工作量估算/依赖关系 | 18 功能优先级排序（ICE/RICE/关键路径） |

## 二、一句话话术（八份文档 3 秒定位）

| 文档 | 一句话 |
|------|--------|
| 11 假设识别与验证 | 哪些假设证伪会连杀一片？先验最致命的 |
| 12 精益画布 | 问题/方案/价值/壁垒/收入/成本，九格自洽吗 |
| 13 北极星指标 | 哪个指标最能代表"我们在创造价值" |
| 14 机会解决方案树 | 期望成果怎么长出机会树和实验田 |
| 15 干系人地图 | 谁有权力又有兴趣？分象限对症下药 |
| 16 Pre-Mortem | 假装已失败，倒推出真正会杀项目的老虎 |
| 17 GTM 策略 | 选哪块市场、走哪条渠道、怎么定价 |
| 18 功能优先级排序 | ICE/RICE 算出来，Kano 看感知，关键路径锁顺序 |

## 三、输入链（验证支线 + 商业支线 + 干系人贯穿）

- 上游：第 2 阶段「用户与价值定义」结论——用户画像、价值主张、ICP、JTBD、定位。
- 验证支线：11 假设识别与验证（假设编号+置信度+杀死链）→ 14 OST（把期望成果拆成机会树，机会评分来自 11 的假设验证状态）→ 16 Pre-Mortem（失败推演，老虎清单呼应 11 的致命假设）。
- 商业支线：12 精益画布（九格商业模式）→ 13 北极星指标（画布的价值用 NSM 量化）→ 17 GTM（画布的收入/成本落到市场选择/渠道/定价）→ 18 功能优先级排序（GTM 节奏决定先打哪类学校/用户，进而决定功能排序；Impact 标尺用 13 NSM，Stakeholder Weight 用 15）。
- 15 干系人地图贯穿：假设的验证要对准正确的人测；GTM 的销售路径要踩准决策链。
- 下游：第 5 阶段 PRD 与排期——18 的 Phase 计划与 Go/No-Go 里程碑直接喂 PRD 范围、验收标准与排期。

## 四、统一写作主线

```
素材进库（定输入）→ 套框架 → 产核心表 → 写"所以呢" → 过及格线
```

每份文档都必须：有结构化框架 → 有 1-3 张核心表 → 有编号体系（假设/风险/机会/渠道）→ 有「所以呢」结论 → 过及格线自检。

## 五、及格线总表

| 文档 | 及格线（每项都须满足） |
|------|---------------------|
| 11 假设识别与验证 | 假设按四风险区分类且有编号；每条标状态+置信度+验证方式；画出依赖/杀死链；有置信度四级量表；有种子期必验 Top 5 与退出条件 |
| 12 精益画布 | 九格都填且有编号；不公平优势给出"难复制+随时间变强"两个判断；有收入结构与成本结构；给出单位经济（CAC/LTV/Payback/边际成本）与敏感性分析 |
| 13 北极星指标 | 说明商业游戏分类；给出候选 NSM 并选 1 个；用 7 标准验证；定义输入指标星座与反指标；有阶段基准+季节性处理+审查节奏 |
| 14 机会解决方案树 | 一棵 OST 只服务一个期望成果；机会用"重要性×(1-满意度)"评分并排序；每个方案有实验八要素；有"已杀死方案"墓地；与产品模块映射 |
| 15 干系人地图 | 识别干系人并建权力×兴趣四象限；分象限沟通策略；画出决策链与影响力网络；有冲突 Playbook 与风险登记册；有 30/60/90 天行动清单 |
| 16 Pre-Mortem | 先定"已失败"场景；风险按概率×影响分 Tigers/Paper Tigers/Elephants 三类；至少 3 只 Launch-Blocking；有 Top 恢复 Playbook 与多时间线推演 |
| 17 GTM 策略 | 市场选择有依据（含模式选择如 B2B/B2C/B2B2C）；有竞品 Battlecards；有定价哲学+方案+弹性+锚定；各渠道有 ROI 模型；有执行日历+上线清单+KPI |
| 18 功能优先级排序 | 用 ICE 与 RICE 量化排序；有 Kano 分类与动态演变；有依赖关系图与关键路径；有人天估算；有风险调整后优先级+Phase 计划+Go/No-Go |

## 六、统一红线（所有文档通用）

1. **量化真实性**：数字必须带算法与来源；财务/单位经济参数标注口径并区分假设与已验证。无法核实的标注「假设/待验证」，禁止编造。
2. **每条假设/风险/机会带编号与标注**：不能只给形容词，要带状态、置信度/概率、影响、验证方式。
3. **结尾必有「所以呢」**：没有决策含义的文档是半成品。
4. **去行业化**：可借用样例的结构与算法，禁止把样例的行业专属素材（政策名、竞品名、领域术语、地域）当作方法论写进框架或搬进新领域文档。
